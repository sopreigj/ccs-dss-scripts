# 装置清单与判据

> 本文逐个说明装置**查什么、判据是什么、有什么局限**。改完东西该跑哪些见
> [`dev-verification.md`](dev-verification.md)；新装置要满足什么见
> [`dev-adding-a-device.md`](dev-adding-a-device.md)。

## 分组

| 组 | 装置 | 需要真板 |
|---|---|---|
| **静态** | `static_checks.js` | 无 |
| **参数层** | `verify_maxpos.ps1` | 无 |
| **退出码契约** | `exitcode.bat` | 部分 |
| **实机审计** | `audit_fix_test.bat` | 大部分 |
| **真板** | `driver_smoke.js`、`phase_d_pipeline.bat` | **是** |

> **与另一套实现的差异**：那边还有一组"镜像 + 桩运行器"的装置，
> 用来覆盖启动器的无人值守分支。**本栈没有那一组，也不需要它**：
> 本栈的启动器只有对话框路径，没有无人值守开关，不存在那条要覆盖的分支。
> 这是两套装置清单之间最重要的差异，见
> [`../../docs/reference/ref-stack-differences.md`](../../docs/reference/ref-stack-differences.md)。

---

## 1. `static_checks.js` —— 静态全套

**查什么**（每项都打印实测计数，不靠断言推断）：

| 项 | 判据 |
|---|---|
| 语法 | 全部 `.js` 都能通过语法检查 |
| 启动器编译 | 每个 `.vbs` 都能被真正编译（注入一条立即退出的语句，只编译不执行） |
| 行尾 | 该 LF 的不含 CRLF；该 CRLF 的不含裸 LF（与 `.gitattributes` 对齐） |
| 编码 | 代码文件里非 ASCII 字节数为 0 |
| 编排层与共享源码的禁词 | 只写 ES3 子集（不用 `let`/`const`/箭头/模板串/`Object.keys`/`JSON.`） |
| 编排层自检 | `orchestration/_selftest.js` 的规则全过 |

**局限**：

- 它不启动任何调试会话，所以对**目标行为一个字都没说**；
- 它检查不出批处理的两个坑（漏 `call`、误用 `timeout`）——那两个只有真跑才暴露；
- 它**不检查文档链接**（本栈的静态检查没有这一项；另一套实现有）。
  所以改文档时要自己确认链接可达，或写一个检查。

**两个宿主**：这个装置用 Node 跑，与 PowerShell 宿主无关。

## 2. `verify_maxpos.ps1` —— 位置参数三方一致

**查什么**：对每个脚本核对三者是否一致：

| 来源 | 是什么 |
|---|---|
| 声明 | 脚本自己在参数规格里写的"最多接受几个位置参数" |
| 期望 | 用法行里写的形状 |
| 行为 | 实际跑一次看它接受/拒绝几个 |

**为什么三者都要**：只比对"声明 = 期望"是循环论证——两者都是人写的。实跑才是独立证据。

**判据**：全部通过且失败数为 0。

**两个宿主都要跑**：5.1 与 7 对原生命令的 stderr 处理不同，只跑一个可能漏掉差异。

## 3. `exitcode.bat` —— 退出码契约回归

**查什么**：五组调用，每组打印实测退出码并与期望值比对。

**其中几项是纯参数层**（不打开会话），所以**不需要真板也能跑**；其余需要真板。

**判据**：每一行的实测值等于它括号里写的期望值。

## 4. `audit_fix_test.bat` —— 实机审计

**查什么**：十条用例，覆盖若干**拒绝路径**（例如参数形状互斥、值放不进位宽、
被主动拒绝的危险操作）与若干**正常路径**。

**其中有一条是解析期拒绝**，不碰硬件；其余需要真板。

**判据**：每一行的实测退出码等于期望值。**被拒绝的用例期望退出码 1**——
"拒绝得对"与"执行成功"是两种不同的正确。

## 5. `driver_smoke.js` —— 驱动契约真板冒烟

**查什么**：驱动名字表里**每一类名字**至少被真实执行一次（参数层、会话层、重量级复合操作、
收尾）。每一步打印一行 `OK <名字>`。

**需要**：真板 + 一个可用的配置文件。观察点那一步需要一个"固件持续写"的地址，
省略时从配置文件的 `WATCH_ADDR` 取。

**判据**：输出里出现"通过"字样，且以 0 退出。

**局限**：它证明的是"名字表里的调用在本技术栈上真的能跑"，不证明业务语义正确。

## 6. `phase_d_pipeline.bat` —— 三步真板管线

**是什么**：把流水线模板的步骤列表填好（检查连接 → 装载并运行 → 装载运行读回一个表达式），
它是**可复跑的回归资产**，不是给用户抄的骨架（那个角色属于 `examples/pipeline_template.bat`）。

**判据**：每一步都打印 `STEP_VERDICT=OK`，最后一行 `PIPELINE_VERDICT=OK`，以 0 退出。

**失败路**：把最后一步的表达式换成一个不存在的符号 → 求值失败 → `STEP_VERDICT=FAIL`、
`PIPELINE_VERDICT=FAIL`，以 1 退出。**这条失败路本身就是"判定翻译真的在工作"的证据。**
