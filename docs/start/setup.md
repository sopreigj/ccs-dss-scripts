# 装好并跑通

## 1. 前置条件

| 需要 | 说明 |
|---|---|
| **CCS 12.2.0** | 12.x 系列（DSS / Rhino 技术栈）。脚本在 12.2.0 上实测。它的 `dss.bat` 位于安装根的 `ccs\ccs_base\scripting\bin\` 下 |
| 一块目标板 + 仿真器 | 本项目实测环境是 C2000 系列芯片 + XDS100 系列仿真器（v1/v2 都接通，见第 5 节） |
| 一个目标配置文件 | 决定"用哪个仿真器、连哪个芯片"，扩展名 `.ccxml`。没有的话在 CCS 里新建：View → Target Configurations → New |
| 一个编译好的固件 | 扩展名 `.out`，同时充当符号表来源 |

## 2. 三个路径键

脚本不假设你的 CCS 装在哪、你的工程在哪。三样东西全部来自配置文件：

| 配置键 | 指向什么 |
|---|---|
| `ccs_root` | CCS 安装根目录（`dss.bat` 在它下面） |
| `ccxml` | 你的目标配置文件 |
| `out` | 你的固件文件 |

**关于路径写法**：`ccs_root` 指向 CCS 安装位置，`ccxml` / `out` 指向你自己的工程位置。
仓库内的**任何**文件都不写死这些路径——它们只活在配置文件里，所以整个仓库可以搬到任何位置。

具体到命令怎么敲，规则是两条：

| 对象 | 怎么写 | 为什么 |
|---|---|---|
| **运行器与脚本** | 用**仓库相对**的写法，并在**仓库根目录**执行 | 启动器会把工作目录钉到仓库根；脚本靠当前目录向上找共享库。所以仓库里就不需要出现任何机器相关的绝对路径 |
| **你自己的目标配置与固件** | **绝对路径** | 它们不在仓库里，而且相对路径会被解析到与调用者无关的位置 |

文档里的命令因此写成"`"%CCS_ROOT%\ccs\ccs_base\scripting\bin\dss.bat"` + 仓库内脚本的相对路径"，
其中 `%CCS_ROOT%` 是**配置键的名字**，不是某个具体的安装位置——你的实际值只在配置文件里。

## 3. 配置：复制—改名—填值

```bat
copy ccs12_2_0.conf.example ccs12_2_0.conf
```

然后编辑 `ccs12_2_0.conf`，把 7 个键改成你的实际值：

| 键 | 含义 |
|---|---|
| `ccs_root` | CCS 安装根 |
| `ccxml` | 目标配置文件 |
| `out` | 固件文件（也是符号表来源） |
| `eval_expr` | 默认读回的表达式（如你自己的一个变量名） |
| `write_expr` | 默认的赋值表达式 |
| `watch_addr` | 默认观察点地址，必须是固件**持续写**的地址 |
| `settle_ms` | 写变量前先让程序跑多少毫秒（默认 500） |

写法：`键=值`，键名大小写不敏感，`;` 开头的整行是注释，值可以含空格与 `=`。
完整说明（含三个入口各自的覆盖链、缺键时的行为、新增一个键的代价）见
[`../reference/ref-configuration.md`](../reference/ref-configuration.md)。

`ccs12_2_0.conf` 是**机器本地文件**，已经在忽略清单里，永远不要提交。

## 4. 验证装对了

在**仓库根目录**执行：

```bat
"%CCS_ROOT%\ccs\ccs_base\scripting\bin\dss.bat" atomic\target\ccs12_2_0_check_connection.js
```

三种结果：

| 你看到 | 含义 | 怎么办 |
|---|---|---|
| `Connection: OK` 然后 `CCS12_2_0_RESULT=OK` | 装对了 | 继续 |
| `Cannot find dss.bat: ...` | `ccs_root` 不对 | 检查配置文件里的 `ccs_root`，或设环境变量（见下） |
| `Configuring target configuration:` 之后报错 | 配置找到了，但目标连不上 | 见下一节 |

<details>
<summary>如果命令没给路径参数，参数是从哪来的？</summary>

脚本在**省略**前导路径参数时会从配置文件补齐（显式给了路径就优先用你给的，且"给一半"仍是用法错误）。
所以上面的命令可以省略路径，正是为了让"装对了没有"这件事一条命令就能验证。
</details>

也可以在 `.vbs` 启动器里设置 **`CCS12_2_0_ROOT`** 环境变量指向 CCS 安装根——它的优先级高于配置文件。
注意它只对 `.vbs` 启动器有效；`examples\*.bat` 用的是另一个同名变量，两者不通用
（覆盖链的完整表见 [`../reference/ref-configuration.md`](../reference/ref-configuration.md)）。

## 5. 目标连不上（`Error -151` 一类）

按这个顺序查，前三步不需要开 CCS：

1. **板子上电了吗、仿真器插好了吗**：设备管理器里应能看到 XDS100 类的 USB 串口设备。
2. **`.ccxml` 里选的仿真器与手上插的是同一个吗**：这是最常见的原因，而且**不能靠连接成功来判断**——
   用 v2 的配置去连 v1 的探针也照样能连上，因为探针身份是从配置文件读的，不是探测出来的。
   核对办法：打开 `.ccxml` 看它声明的连接类型，与设备管理器里实际插着的型号比。
3. **换仿真器（v1 ⇄ v2）**：改 `.ccxml`，然后重新设 `ccxml` 配置键指向新文件即可；脚本不用动。
   一个工程里散落多份同名 `.ccxml` 是常见事故源，确认你改的是配置键指向的那一份。
4. **还有别人占着调试器吗**：上一次没退出干净的调试进程会占住探针，表现为连不上。
   关掉 CCS GUI 与遗留的调试进程再试。
5. 换芯片（不是换同系列的另一块板）时，除了新建 `.ccxml`，还要注意内存位宽、寄存器名、
   符号与表达式的作用域差异，见 [`../guides/gu-troubleshooting.md`](../guides/gu-troubleshooting.md)。

## 6. 换硬件时要改什么

| 你换了 | 要改 | 不用改 |
|---|---|---|
| 同型号的另一块板 | 只改 `ccxml` 与 `out` | 所有脚本 |
| 仿真器型号（v1 ⇄ v2） | `.ccxml`（在 CCS 里改并另存），再改 `ccxml` 键 | 所有脚本 |
| 芯片型号 | 新建 `.ccxml`；核对固件与符号表；注意内存与寄存器差异 | 所有脚本 |
| 只换固件 | 只改 `out`（以及配方四个键） | 所有脚本 |
