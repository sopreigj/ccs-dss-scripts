# 仓库内的贡献约定

> 面向"要改这个仓库的人"。给外部 PR 的更短版本在根
> [`CONTRIBUTING.md`](../../CONTRIBUTING.md)。本文补充仓库内部的更深一层约定。

## 1. 一个概念一个词

本项目把"同一个概念只用一个名字"当硬规则。新增脚本、函数、配置键之前，
先查受控词汇表 [`../reference/ref-terms.md`](../reference/ref-terms.md)：

- 如果那个概念已经有词，就用它，**不要造同义词**；
- 如果确实需要新词，把它加进词汇表，并写清它与近邻概念的区别。

## 2. 一层只做一件事

| 层 | 只做 | 不做 |
|---|---|---|
| `atomic/` | 参数解析、开一个会话、做一件事 | 跨步骤编排 |
| `workflows/` | 纯接线，把共享 main 与驱动接起来 | 业务逻辑、参数解析、直接调引擎 |
| `orchestration/` | 会话内动作的顺序与判定口径 | 任何技术栈相关的调用形状 |
| `session/` | 参数校验、会话语义、结果表达、驱动门面 | 决定"做什么" |

**判据**：如果你写的东西需要知道"这本技术栈怎么调"，它就不该在 `orchestration/` 里。

## 3. 代码约束（机械检查）

| 约束 | 谁检查 |
|---|---|
| `.bat`/`.vbs`/`.conf` CRLF；`.js`/`.md`/`.ps1` LF | 静态检查 |
| 代码文件 ASCII-only | 静态检查 |
| 编排层与共享源码的 ES3 禁词 | 静态检查 |
| 每个脚本声明接受的位置参数个数 | 参数层装置 |
| 启动器可编译 | 静态检查 |

## 4. 文档同步义务

**文档与代码同笔提交。** 具体到"改了什么必须改哪些文档"：

| 改了 | 必须同步 |
|---|---|
| 脚本的参数形状或输出 | 脚本头部用法行 + [`../reference/ref-scripts.md`](../reference/ref-scripts.md) + 装置表 |
| 配置键或覆盖链 | [`../reference/ref-configuration.md`](../reference/ref-configuration.md) 的三张表 + 配置模块 + 示例 |
| 退出码语义 | [`dev-launcher-contract.md`](dev-launcher-contract.md) + 所有引用它的位置 |
| 新增/删除脚本 | 本目录与 [`../reference/`](../reference/) 相应篇 + `test/README.md` 的装置表 |
| 驱动导出的名字 | 名字表 + 编排层自检（**并且要确认另一套实现也能接受**，因为契约共用） |
| 新增一层或改变分层 | [`dev-architecture.md`](dev-architecture.md) |

## 5. 提交纪律

- 一次提交只做一件事；信息用 `feat:` / `fix:` / `docs:` / `test:` 前缀，正文写清**改了什么都为什么**。
- **改名/搬文件要一次做完**：同一次提交里改文件名、改引用、改文档。
- **破坏性变更要在信息里显式说明**：改参数形状、改配置键、改判定方式都算。
- **改了驱动名字表要想到另一侧**：那份契约是两套实现共用的。

## 6. 不写进仓库的东西

| 不写 | 原因 |
|---|---|
| 机器相关的绝对路径 | 仓库要能搬到任何位置；文档、脚本、注释一律用相对写法或配置键的说法 |
| 你的工程名、固件名、符号名、台架地址与读数 | 换成通用示例（`your_symbol.Var`、`0xC000`） |
| 设备序列号、串口号 | 换成型号与占位 |
| 内部开发过程：编号体系、工作日志、任务队列、会话记录 | 只写"现象 → 原因 → 判据 → 怎么避免" |
| 可推断作者身份的信息 | 不写 |
| 编辑器/工具的私有配置 | 已在忽略清单里 |

## 7. 新增一个配置键的真实代价

加一个键看起来只是"在示例里加一行"，实际上要同时改：

1. 配置模块的读取与键名；
2. 配置文件示例；
3. [`../reference/ref-configuration.md`](../reference/ref-configuration.md) 的三张覆盖链表；
4. 真正读这个键的脚本；
5. 缺键时的错误文案与行为。

而且**旧的配置文件不会因此报错**（它只是缺这个键）。所以：**能做成命令行参数的就不要做成配置键。**

## 8. 文档与另一套实现的关系

本仓库与另一套实现的**文档结构尽量镜像**，因为读者可能两套都用。
但遇到确实不同的地方（判定方式、参数传递、语言约束、装置形态）：

- **不要为了对称而隐去差异**；
- 在文中显式标注差异，并指到
  [`../reference/ref-stack-differences.md`](../reference/ref-stack-differences.md)；
- 改了本仓库的差异面（尤其是判定与契约），要同时考虑那份对照表是否需要更新。
