# 判定与启动器契约

> **改任何脚本之前先读这篇。** 这里定义的是"脚本怎么被判成功、怎么被启动"这件事，
> 它是全仓唯一的权威出处——其他文档只引用不重复。

## 1. 判定：退出码 + 输出里的原因

| 情况 | 退出码 | 原因在哪 |
|---|---|---|
| 成功 | `0` | — |
| 任何失败（用法错误、文件不存在、会话失败、操作失败） | `1` | **输出里** |

本技术栈的**运行器会把脚本的退出状态透传出来**，所以退出码是可靠的判据。
这与另一套实现**相反**——那边的运行器不透传退出码，
只能看 stdout 上的一次性结果标记行。

**原因不在退出码里**，所以调用方要把输出收下来：

```bat
call "%RUN%" workflows\ccs20_0_1_load_run.js "<ccxml>" "<out>" > "%LOG%" 2>&1
if errorlevel 1 (
    echo FAILED & type "%LOG%"
    exit /b 1
)
```

**用法错误也走同一条路**：报错 + 打印用法 + 以 1 退出。所以调用方只需要处理一种失败形状。

## 2. 脚本怎么被启动（参数从哪来）

```
运行器 run.bat  →  引入脚本  →  脚本自己从第 3 个位置起读参数
```

运行器会在命令行里插入脚本名，所以：

- **必须经运行器调用**；直接 `node <脚本> <参数>` 会让第一个参数被吃掉；
- 入口脚本必须从**仓库内**启动（共享库按当前目录向上解析）；
- `.js` 与它的 `.vbs` 必须同目录成对存在。

> **与另一套实现的结构差异**：那边每个脚本开头有一段**逐字相同**的"引导块"，
> 负责按绝对路径装载共享库并断言哨兵（因为那里的装载失败不抛异常）。
> **本栈没有引导块**——模块解析会正常报错，所以不需要那种防护。
> 因此那边的"引导块一致性检查"与相关排障经验，在本栈都不适用。

## 3. 启动器（`.vbs`）

| 用法 | 行为 |
|---|---|
| 双击 | 每个位置参数弹一个框问 |
| 带参数调用 | 不弹框；参数顺序与同名 `.js` 完全一致 |

启动器负责的事：

- 把工作目录**钉到仓库根**（所以用启动器不必关心当前目录）；
- 解析配置文件、按键回落到环境变量；
- 把参数拼成命令行，跑运行器，收下输出；
- 按退出码判定成败，失败时把输出打出来。

**两个容易踩的点**：

- **对话框被取消 → 以 1 退出**（取消等于什么都没做，不能算成功）；
- **失败原因显示在弹窗里**，所以自动化场景应该直接调 `.js`。

> **本栈没有"完全不弹框"的开关**（另一边有）：无人值守场景请直接调 `.js`，
> 或设 `CCS_EVAL_EXPR` / `CCS_WRITE_EXPR` 这类环境变量把值喂进去。
> 这是两套之间一处确实无法镜像的差异，见
> [`../reference/ref-stack-differences.md`](../reference/ref-stack-differences.md)。

## 4. 环境变量与配置的关系

| 变量 | 谁用 | 说明 |
|---|---|---|
| `CCS20_0_1_ROOT` | `.vbs` 启动器 | 决定**运行器在哪**；它换不了板子、也换不了固件 |
| `CCS_CCXML` / `CCS_OUT` | 启动器与脚本 | 目标配置 / 固件的默认值 |
| `CCS_EVAL_EXPR` / `CCS_WRITE_EXPR` | 表达式类脚本 | 默认的求值 / 赋值表达式 |
| `CCS_SYMBOLS` | 表达式类脚本 | 符号表路径 |

**换板子、换固件改的是配置文件里的 `CCXML` 与 `OUT`**，不是 `CCS20_0_1_ROOT`。
完整覆盖链见 [`../reference/ref-configuration.md`](../reference/ref-configuration.md)。

## 5. 参数里的特殊字符

本栈的运行器**原样透传**参数，所以含 `=` 与空格的表达式可以直接写在命令行上。

**唯一的坑在 PowerShell**：用 `cmd /c "..."` 拼命令时，PowerShell 会先处理一遍引号，
内部引号可能被吃掉，表现为"参数形状不对"。稳妥做法：直接用 `cmd`，或让表达式从环境变量进来。

> 另一套实现**必须**走环境变量（它的运行器会吃 `=` 与空格）。所以那边的做法在本栈是
> "可选"而不是"必须"——见 [`../reference/ref-stack-differences.md`](../reference/ref-stack-differences.md)。

## 6. 改这一层的后果

| 你改了 | 必须同步 |
|---|---|
| 退出码语义 | 所有使用退出码的位置 + 全仓文档 + 判定原语 |
| 参数从第几个位置起读 | 所有脚本的调用形态 + 运行器约定 + 文档 |
| 配置键或覆盖链 | [`../reference/ref-configuration.md`](../reference/ref-configuration.md) 的三张表 + 配置模块 + 示例 |
| 驱动导出的名字 | 名字表 + 编排层自检（并且要考虑另一套实现也共用这份契约） |
