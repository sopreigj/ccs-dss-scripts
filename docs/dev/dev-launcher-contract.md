# 启动器与判定契约

> **改任何脚本之前先读这篇。** 这里定义的是"脚本怎么被判成功、怎么被启动"这件事，
> 它是全仓唯一的权威出处——其他文档只引用不重复。

## 1. 判定：结果标记行

| 情况 | 输出 | 退出码 |
|---|---|---|
| 成功 | stdout 上恰好一行 `CCS12_2_0_RESULT=OK` | 0 |
| 失败 | stdout 上恰好一行 `CCS12_2_0_RESULT=FAIL <原因>` | 1 |

**为什么不用退出码**：底层运行器不把脚本的退出状态变成自己的进程退出码。实测几种情形
（脚本以非零码退出、自然结束、脚本路径根本不存在）拿到的进程退出码都是 0。
所以退出码既没有原因，也分不清"跑完了"与"脚本没找到"。

**顺序也是契约**：

- `finishOk()`：**先**收尾（停机 + 释放会话），**再**打成功标记；
- `finishFail(原因)`：**先**打失败标记，再强制停机、释放，最后以 1 退出。

所以"看到标记"意味着活已经干完（成功）或已经确定失败，而不是"刚开始"。

**原因只活在标记行里**。任何调用方与看日志的人，唯一的解释来源就是这一行。

## 2. 引导块

每个入口脚本（`atomic/` 与 `workflows/` 下的 `.js`，以及 `test/driver_smoke.js`）开头有
**逐字节相同**的一段代码，做四件事：

1. 从当前目录**向上**寻找共享库；
2. 确认它存在；
3. 装载它；
4. 断言哨兵常量。

第 4 步是关键：本技术栈的装载操作**装载失败不抛异常**（只打印一行然后照常执行），
没有哨兵断言的话，"装载失败"会静默地变成"后面每行都报错"。

**由引导块负责的等价规则**：

- 脚本必须从仓库内启动（否则第 1 步找不到）；
- `.js` 与它的 `.vbs` 必须同目录成对存在（启动器靠自身位置找同名 `.js`）；
- 共享库与脚本不能被拆散单独复制出去。

**机器复查**：`test/verify_static.ps1` 会切片比对这段块在全仓是否逐字节一致，并给出可复算的摘要。
摘要值会因为块内任何字节变化而变，所以"改了但没改齐"会被直接抓住。

## 3. 启动器（`.vbs`）

| 用法 | 行为 |
|---|---|
| 双击 | 每个位置参数弹一个框问 |
| 带参数调用 | 不弹框；参数顺序与同名 `.js` 完全一致 |
| 无人值守模式 | 一个框都不弹，每个框变成一行控制台输出 |

启动器负责的事：

- 把工作目录**钉到仓库根**（所以用启动器不必关心当前目录）；
- 解析配置文件、按键回落到环境变量；
- 把参数拼成命令行，跑底层运行器，收下 stdout + stderr；
- 按**最后一个**标记行判定成败，失败时把标记行与末尾输出一起显示。

**两个容易踩的点**：

- **对话框被取消 → 以 1 退出**（取消等于什么都没做，不能算成功）；
- **失败原因只在弹窗里**，所以自动化场景应该直接调 `.js`。

## 4. 只读 / 改状态：无人值守模式下能不能用默认值

启动器的默认值只是**示例值**。在无人值守模式下：

| 类别 | 行为 | 依据 |
|---|---|---|
| **只读** | 允许采用默认值 | 启动器头部调用了"声明只读" |
| **改状态** | **拒绝**采用默认值，参数必须写在命令行上 | 未声明只读（这是默认类别） |

**判据不是"它改不改目标"，而是"不给参数能不能跑对"**。例："校验程序"只读，
但它必须知道比对哪个固件文件，没有可信默认值，所以它同样拒绝回落。

**默认方向是安全的**：忘记声明的后果是"变得更严格"，不会"放松"。

分类表同时存在于两处并**双向核对**：每个启动器头部的声明，与
`test/drive_checks.ps1` 顶部的分类表。哪一侧被悄悄改掉，装置都会红。

## 5. 环境变量与配置的关系

| 变量 | 谁用 | 优先级 |
|---|---|---|
| `CCS12_2_0_ROOT` | 只有 `.vbs` 启动器 | 高于配置文件 |
| `CCS_ROOT` | 只有 `examples\*.bat` | **低于**配置文件（配置文件里读到就覆写） |
| `CCS_CCXML` / `CCS_OUT` | 启动器与示例 | 中间一级 |
| `CCS_EVAL_EXPR` / `CCS_WRITE_EXPR` / `CCS_SYMBOLS` | 表达式与符号传递 | 见脚本说明 |
| `CCS12_2_0_NONINTERACTIVE` | 所有 `.vbs` | `1` = 不弹框 |

**两个 `*_ROOT` 不是同一个变量**，这是设计上的历史包袱，但它是**按入口分别成立**的：
`.vbs` 与 `examples\*.bat` 各有各的链。完整覆盖链见
[`../reference/ref-configuration.md`](../reference/ref-configuration.md)。

## 6. 改这一层的后果

| 你改了 | 必须同步 |
|---|---|
| 标记行文字 | 所有解析标记的地方（示例、装置、模板）+ 全仓文档 |
| 引导块内容 | 全仓每一个入口脚本（装置会告诉你有没有改齐） |
| 退出码语义 | 文档里所有提到判定的地方 + 判定原语 |
| 只读 / 改状态分类 | 启动器头部声明 + `test/drive_checks.ps1` 的分类表 |
| 配置键或覆盖链 | [`../reference/ref-configuration.md`](../reference/ref-configuration.md) 的三张表 + `.vbs` 解析 + 示例 |
