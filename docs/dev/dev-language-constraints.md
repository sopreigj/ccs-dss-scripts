# 语言约束：三种宿主语言各自的老版本

这个项目同时被三种老语言执行：脚本本体跑在 **Rhino ES3** 上，启动器是 **VBScript**，
入口与流水线是 **cmd 批处理**。三者都有各自的历史包袱，本文集中列出——
这是新人最容易写出"看着对但跑不了"的地方。

静态门禁会机械拦住其中一部分，但**不是全部**：有些问题只有在真跑时才暴露。

## 1. 脚本本体：Rhino ES3

**不存在**：

| 不能用 | 替代 |
|---|---|
| `let` / `const` | `var` |
| 箭头函数 | `function` |
| 模板字符串 | 字符串拼接 |
| `Object.keys` | `for-in` + 判断自有属性 |
| `JSON.` 系列 | 手写拼接与解析 |
| `Array.prototype.map` / `forEach` | 手写 `for` 循环 |
| `String.prototype.trim` | 手写去空白 |

**存在的**：`Array.indexOf`（这是个例外，可以放心用）。

**为什么这么严**：脚本本体的运行时是很老的 Rhino（2006 年的 ES3 级别）。门禁会扫描这套禁词，
所以写错了会在提交前被拦下，而不是运行时出怪事。

## 2. 脚本本体的编码坑

脚本按**平台字符集**读取源码文件。在中文 Windows 上那是 GBK，所以：

- `.js` / `.vbs` / `.bat` **一律 ASCII**；
- 中文只写进 `.md`；
- 非 ASCII 字节会被解错，**甚至吞掉换行**，导致语法错误或诡异的解析结果。

配置文件另有专门的 UTF-8 读取实现，所以配置里可以有中文注释——**但代码文件不行**。

## 3. 启动器：VBScript

- 没有内建的"给参数加引号"函数，脚本里自己实现了一个。**所有**要拼进命令行的字符串
  都必须过它，否则含空格的参数会被拆开；
- 完成提示是**阻塞弹窗**：没有人点的会话里会一直等。所以有无人值守模式；
- 对话框被取消时应当按失败处理（取消 = 什么都没做）；
- 声明区必须在文件最前，装载共享库要用"装载 + 断言"的写法（装载失败不抛异常）。

## 4. 入口与流水线：cmd 批处理

| 约束 | 后果 |
|---|---|
| 调用另一个 `.bat` 必须写 `call` | 漏了会**静默结束**后续步骤，而退出码仍然成功 |
| 延时要与判定方式配合地写 | `timeout` 在标准输入被重定向时会跳过延时；用 `ping` 更稳 |
| 参数里不能有 `=` 或空格 | cmd 会在解析阶段中止，运行时根本没起来（表现为退出码 255、没有标记行） |
| 行尾必须是 CRLF | 用编辑器默认可能写成 LF，cmd 会把注释行当命令执行 |
| 变量展开时机 | `%变量%` 在命令执行前展开；读退出码要在**下一行**读 |

## 5. 谁负责拦什么

| 语言 | 门禁能自动拦的 | 只能靠人的 |
|---|---|---|
| 脚本本体 | 语法（`node --check` 级的检查）、ES3 禁词、编码、行尾 | 语义错误、属性名写错 |
| 启动器 | 编译检查、参数个数的声明与用法行是否自洽、非交互分类是否与声明一致 | 对话框的排版、文案是否清楚 |
| 批处理 | 行尾、编码 | `call` 漏写、`timeout` 误用（**这两条只有真跑才暴露**） |

## 6. 三条来自实践的提醒

1. **改 `.vbs` 之后必须跑一次编译检查**：纯语法检查看不出"运行时才会被解析到的东西"，
   所以装置会真的编译一遍每个 `.vbs`。
2. **批处理的两个坑不能靠静态检查发现**：`call` 漏写与 `timeout` 误用都会"看起来成功"。
   改动这类文件后，**用一次真实调用验证**，不要只看它有没有报错。
3. **参数里的特殊字符**：只有真的跑一遍才知道 cmd 会不会吃掉它。相关处置见
   [`../reference/ref-decision-tables.md`](../reference/ref-decision-tables.md) 表 3。
