# 踩坑账本

> 这里记的是"看起来对、跑起来不对"的事。每条都是：**现象 → 原因 → 判据 → 怎么避免**。
> 只写结论与判据，不写是谁在什么时候发现的。

## 1. 批量改前缀，把已经是新名的文本又改了一遍

**现象**：全仓把旧前缀替换成新前缀之后，出现"新前缀套了两层"的东西
（例如版本串变成 `..._2_0_2_0...`），而且只在**原本就含新名**的位置出现。

**原因**：替换规则匹配的是短前缀，而有些文本里已经有"短前缀 + 版本后缀"的形式。
一次遍历里对同一段文本连续命中，就会把后缀当成前缀的一部分再补一次。

**判据**：替换后全仓搜"**替换结果套两层**"的形状（把新后缀重复一次当搜索词）。
命中数应为 0。

**怎么避免**：
- 用一次遍历的替换（不是对同一段文本反复替换），并让规则**排除已经带新后缀的位置**；
- 替换后再搜旧名字是否还有残留（两条搜索都要做：坏形状 + 残留）。

## 2. 同一份配置，两个入口读的是不同文件名

**现象**：配置文件明明在，脚本却报"没有配置"。只有**省略路径参数**的那种调用会报，
显式传路径的调用一切正常。

**原因**：改名时只改了一部分读取点。启动器与示例读的是新名字，而脚本本体内嵌的那个解析器
还在找旧名字。两条读取路径不一致，于是就出现了"文件在但读不到"。

**判据**：全仓搜配置文件名，**所有**读取点必须是同一个名字。
这条搜索要覆盖脚本本体、启动器、示例与文档。

**怎么避免**：改名以后，专门跑一次"**省略参数的调用**"——因为显式传参的路径不会碰配置读取，
常规测试覆盖不到它。**这是最容易漏的一条。**

## 3. 管道把真实的退出码吃掉了

**现象**：命令明明失败，量到的退出码却是 0。

**原因**：把原生命令的输出接进 PowerShell 管道之后，`$LASTEXITCODE` 变成管道里最后一个
cmdlet 的退出码，不再是那个原生命令的。

**判据**：要看真实退出码，就在**不接管道**的情况下读，或者让脚本自己把结论打印出来。

**怎么避免**：判断成败时优先看脚本自己打印的判定行；确实要看退出码时，
写进临时变量或者另起一条命令读。

## 4. 引导块的摘要值必须"整行切片"才能复算

**现象**：按文档里的命令复算引导块摘要，得到的是一个**任何文件里都不存在**的值。

**原因**：切片方式不对。如果用一个"匹配到某个字面量就结束"的正则，匹配会在那一行的开头
就结束，于是只取到收尾行的前几个字符——块少了一截，摘要自然对不上。

**判据**：复算出的摘要必须与门禁打印的一致；如果得到一个"很眼熟但从没见过的值"，
先怀疑切片边界。

**怎么避免**：按**整行**切片（从起始行到下一个符合前缀的行），不要用会把行截断的匹配方式。
门禁里已经这么实现，复算时照抄它的做法。

## 5. 参数里的 `=` 或空格会让运行器在解析阶段就中止

**现象**：命令退出码 255，输出里连判定行都没有，报错是"某处 unexpected"。

**原因**：cmd 在解析阶段就中止了，宿主运行时根本没起来——所以不是脚本逻辑的问题，
而是**命令根本没被执行**。

**判据**：**输出里一行判定都没有**，就是这一类。

**怎么避免**：带 `=` 或空格的表达式走环境变量通道，见
[`../reference/ref-decision-tables.md`](../reference/ref-decision-tables.md) 表 3。

## 6. 同一条命令，一个宿主通过、另一个宿主失败

**现象**：同一个装置在 PowerShell 7 下全过，在 Windows PowerShell 5.1 下报终止错误，
而且**跳过**了最后几项检查。

**原因**：5.1 会把原生命令写到 stderr 的内容提升成错误记录，遇到"出错即停"的设置就变成
终止错误。而装置自己的负对照恰好是故意往 stderr 写东西的。

**判据**：任何装置必须在**两个宿主**下跑且结论一致。只在一个宿主下通过是缺陷。

**怎么避免**：调用原生命令时临时把"出错即停"放开，跑完再恢复；
并把这个装置纳入"两宿主都跑"的清单。

## 7. 判定原语把输出"消费"掉了

**现象**：用判定原语包住一个脚本之后，找不到被包脚本原来打印的输出。

**原因**：判定原语是**翻译器**，不是透传器：它把被包脚本的判定翻译成自己的那一行，
成功时不再回显。这是刻意的设计（否则每一层都要重复解析）。

**判据**：需要原始输出或原始判定 → 直接调脚本，不要经它。

## 8. "写进去了"和"值留住了"不是一回事

**现象**：赋值表达式报告成功，随后读回却是旧值。

**原因**：程序启动阶段的初始化把变量又赋了一遍，覆盖了刚写入的值。

**判据**：只有"写 + 让程序跑一段 + 回读"三步都做过，才能说"写入生效"。

**怎么避免**：用带"先等一段再写"的工作流，而不是先写再运行。

## 9. 相对输出路径会落到与调用者无关的地方

**现象**：导出文件明明成功了，但在当前目录与仓库里都找不到。

**原因**：相对输出路径由调试器一侧解析，落点与调用者的当前目录无关。

**判据**：找不到产物时，先怀疑它是相对路径。

**怎么避免**：输入与输出**都**用绝对路径。本项目在参数层强制这一点。

## 10. 改了共享的一段代码，只改了一部分文件

**现象**：装置报"这段代码在不同文件里不一致"。

**原因**：逐字节相同的那段共享代码（引导块）只能整段复制，手打或只改一处都不行。

**判据**：装置会给出一致的摘要值，不一致就会被点名。

**怎么避免**：改这类共享段时，用脚本做整仓同步，然后跑装置确认摘要值只有一种。

## 11. 删掉一个脚本，却留下了引用

**现象**：读者按文档去找一个已经不存在的东西。

**原因**：删除只做了"删文件"，没有同步文档、示例、装置表与注释。

**判据**：删除后全仓搜索它的名字（含文档与注释），命中数应为 0。

**怎么避免**：把"删除"当成一个有清单的操作，见
[`dev-adding-a-script.md`](dev-adding-a-script.md) 第 4 节。
