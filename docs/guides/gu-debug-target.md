# 目标：断点、单步、观察点

这三件事都**依赖会话内的状态**，所以都只有工作流脚本，没有对应的原子脚本。

| 想做什么 | 用哪个脚本 |
|---|---|
| 设一个断点并运行到它 | `workflows/ccs20_0_1_run_to_bp.js` |
| 单步 N 次并打印每次的 PC | `workflows/ccs20_0_1_step.js` |
| 问"**是谁**在改这个变量" | `workflows/ccs20_0_1_watch_write.js` |

> 另有一套 另一套实现在这里多一个脚本（在断点上挂一个写动作）。
> 本技术栈没有对应能力，所以**本仓库没有那个工作流**——这是两套之间少数**无法镜像**的差异之一，
> 见 [`../reference/ref-stack-differences.md`](../reference/ref-stack-differences.md)。

## 为什么没有"设断点"和"跑到断点"两个独立脚本

断点是**会话的子对象**：会话关闭时它被销毁，没有任何接口能把它重新挂到新会话上。
所以"设断点"与"跑到断点"必须落在同一个脚本里——否则第二步开的是新会话，
里面根本没有你刚设的那个断点，它只会变成一次自由运行。

想让这件事成立，可以自己试一次：一条命令设断点、另一条命令运行，看它是不是停在你期望的位置。
预期结果是不会。

## 跑到断点：一个容易误判的现象

加载程序结束时，目标通常**已经停在程序入口**。此时如果你在入口处设断点再运行，
"运行"这个动作永远不会重新进入它停着的那条指令——所以脚本把这种情况当作**已经到达**，
而不是超时。

这是正常路径，不是失败。判断是不是真的到达，看它报告的 PC 与断点地址是否一致。

几种如实报告的结局：

| 结局 | 含义 |
|---|---|
| 已到达（PC 正好在断点地址） | 成功，即使没有"运行"这一步 |
| 运行后停在断点地址 | 成功 |
| 停机了，但 PC 不在断点地址 | **不算命中**，脚本会如实报告 |
| 超时仍没停 | 失败，带原因 |

## 单步

| 参数 | 含义 |
|---|---|
| `<count>` | 走几步 |
| `--from <位置>` | 先从当前位置运行到这里，再开始单步 |
| `--kind into\|over\|out\|asm` | 单步类型 |
| `--timeout <ms>` | 等待目标停下来的超时 |

两点注意：

- **单步要求目标已经停机**。脚本会先检查状态，目标在运行就直接以明确的原因失败，
  而不是硬走一步。
- **汇编级单步（`--kind asm`）**在本技术栈上走的是底层提供的汇编级单步调用；
  另一套实现里这个能力存在栈间差异，本栈没有这个限制。

## 观察点：回答"谁在改这个变量"

硬件数据观察点会在**执行那次访问的指令上**把 CPU 停住，所以停机时的 PC 就是"凶手"的地址。
脚本会把这个 PC 打出来。

- **观察点是硬件资源**：数量受目标上的硬件资源预算限制，加太多会失败。
- 切换观察点类型会**重建它的属性集合**，所以属性标识在切换后失效，必须重新定位。
  这件事已经在共享层里处理掉了，你不需要关心，但如果你要自己写原生调用，要知道这个坑。
- **PC 反查源码行是 GUI 的活**：这套接口没有"地址 → 符号"的查询能力，脚本只能给出 PC。
- 观察点要挂在**固件持续写入**的地址上，否则它永远不会触发。挂在一个"没人写"的地址上等它触发，
  结果一定是超时。

## 例：跑到 main

```bat
"%CCS_ROOT%\ccs\scripting\run.bat" workflows\ccs20_0_1_run_to_bp.js "<ccxml>" "<out>" main
```

如果加载结束后目标已经停在 `main`，你会看到它报告"已经在那里"——这是成功。

## 例：看谁在改某个变量

```bat
:: 第 3 个参数是地址；省略则读配置文件里的 WATCH_ADDR
"%CCS_ROOT%\ccs\scripting\run.bat" workflows\ccs20_0_1_watch_write.js "<ccxml>" "<out>" 0xC000
```

## 采样：定期读一批表达式

不属于调试三件事，但常与它们一起用：

```bat
"%CCS_ROOT%\ccs\scripting\run.bat" workflows\ccs20_0_1_sample_exprs.js "<ccxml>" "<out>" 200 5 "<csv_file>" "your_symbol.Var" "PC"
```

含义是"每 200 毫秒采一次，共 5 次，把结果写进这个 CSV"。两条语义要记住：

- **采样不会停住目标**，每次取值都是一个瞬时读，所以多字长变量可能被抓到"改到一半"的状态；
- **CSV 的时间列是实测的**（从采样开始算的真实耗时），不是名义间隔，所以它比"200 毫秒 × 序号"更可信。

文件格式与落点见 [`../reference/ref-file-formats.md`](../reference/ref-file-formats.md)。
