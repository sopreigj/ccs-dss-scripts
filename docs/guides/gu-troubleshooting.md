# 排障：按症状进门

**第一步永远是看退出码与输出**：

- 退出码 `0` = 成功；
- 退出码 `1` = 任何失败（用法错误、文件不存在、会话失败、操作失败），**原因在输出里**。

> **本栈与另一套实现在这里相反**：那边退出码不可靠，只能看 stdout 上的
> 结果标记行。如果你是从那一边过来的，先记住这条差异。

---

## 1. 提示找不到运行器 / `CCS_ROOT not configured`

两个入口用不同的链去找 CCS 安装位置：

| 入口 | 找法 |
|---|---|
| `.vbs` 启动器 | 环境变量 `CCS20_0_1_ROOT` > 配置文件 > **报错** |
| `examples\*.bat` | 配置文件 > 继承来的 `CCS_ROOT` > **报错 exit 1** |

**环境变量 `CCS20_0_1_ROOT` 只决定运行器在哪**：设了它换不了板子、也换不了固件
——那两样看 `CCXML` 与 `OUT`。完整覆盖链见
[`../reference/ref-configuration.md`](../reference/ref-configuration.md)。

## 2. 连不上目标（`Error -151` 一类）

按这个顺序查（前两步不需要开 CCS）：

1. 板子上电了吗？仿真器插好了吗？设备管理器里能看到探针设备吗？
2. **配置里声明的仿真器型号与手上插的是同一个吗？** 这是最常见的原因，而且很反直觉：
   核名那一行来自配置文件，不是探测结果，所以型号写错也可能"连上"。要拿配置文件与
   设备管理器**人工对账**。
3. 上一次调试进程是不是没退干净、还占着探针？（关掉 GUI 与遗留进程再试。）
4. 该 `.ccxml` 是不是被别的工程覆盖过？散落多份同名配置文件是常见事故源。
5. 换芯片（不是同型号的另一块板）还可能遇到内存位宽、寄存器名、符号作用域的差异。

## 3. 变量读不出来：`identifier not found`

读符号名需要**会话里有符号表**。两条路：

- 先用 `loadProgram` 烧一次（符号表随程序进会话）；
- 或给表达式类脚本显式指定固件文件（`--symbols "<out>"`）。

注意 `--symbols` 的值必须是可用路径；给了**空值**会直接报用法错误，而不是"静默地不加载符号表"。

## 4. 单步 / step out 失败

- **源码级单步需要符号信息**；没有符号就退回汇编级单步。
- **目标必须先停机**。目标在运行时不单步，脚本会以明确原因失败。
- `--from <位置>` 是"先运行到这里再单步"；如果目标已经停在该位置，脚本当作已到达，不会空等。

## 5. 表达式带空格、括号、星号时怎么传

本栈的运行器**原样透传**参数，所以一般情况下直接加引号写就行。

**如果是在 PowerShell 里拼 `cmd /c "..."`**：PowerShell 会先处理一遍引号，内部的引号可能被
吃掉，表现为"参数形状不对"或"位置参数过多"。三个稳妥做法：

1. 直接用 `cmd` 执行 `.bat`（CI 里推荐）；
2. 把表达式放进环境变量：`CCS_EVAL_EXPR` / `CCS_WRITE_EXPR` / `CCS_SYMBOLS`；
3. 用 PowerShell 的调用运算符配合数组传参，而不是拼一个字符串。

## 6. 流水线里的两个坑：`call` 与 `timeout`

| 坑 | 现象 | 怎么办 |
|---|---|---|
| 漏写 `call` | 第一步之后**静默结束**，整条流水线退出码仍是 0 | 每个链式调用都写 `call` |
| 用了 `timeout /t` | 标准输入被重定向时直接报错并**跳过延时** | 用固定次数的 `ping` |

这两个坑静态检查抓不到，只能靠真跑或代码审阅。

## 7. 写完变量读回来还是旧值

写入被程序启动阶段的初始化覆盖了。解决方式是"先让程序跑过启动阶段、再写、再运行、再回读"：

```bat
"%CCS_ROOT%\ccs\scripting\run.bat" workflows\ccs20_0_1_load_write_run_read.js "<ccxml>" "<out>" 2000 --settle 500 --set "your_symbol.Var = 1" --read "your_symbol.Var"
```

详见 [`gu-modify-state.md`](gu-modify-state.md)。

## 8. 这些脚本能用在别的项目上吗

能。脚本不依赖任何特定固件，只依赖三样东西：CCS 安装位置、目标配置文件、固件文件。
换项目时改配置文件里的 7 个键即可，脚本一行都不用动。

## 9. 双击 `.vbs` 没反应 / 卡住 / 取消了会发生什么

- 启动器用对话框问参数；**完成提示也是弹窗，在没有焦点、也没有人点的会话里会一直等**；
- 对话框被**取消**时，启动器以 1 退出（取消等于什么都没做）；
- 失败原因显示在弹窗里，所以自动化请直接调 `.js`。

> 本技术栈**没有**一个"完全不弹框"的开关（另一边有）。所以无人值守场景请直接用 `.js`

## 10. 报 `Cannot find module ...`（共享库没找到）

脚本经运行器启动时会按当前目录向上寻找共享库。出现这条说明：

- 当前目录不在仓库内 —— 从仓库根（或仓库内任意子目录）执行；
- 或者共享库文件被挪走/改名了 —— `.js` 与它的 `.vbs` 必须同目录成对存在，不能单独搬。

> 本栈与另一边在这里的机制**不同**：另一边每个脚本开头带一段逐字相同的"引导块"做这件事，
> 本栈靠运行器与模块解析。所以那条"引导块"的排障经验不适用于本栈。

## 11. 同一地址每次读到的值都不一样，有时还是 0

**这是预期行为**，不是板子或脚本坏了。

每条命令自成一个会话，读到的是**本会话开始之后**的活值。如果那个地址是固件在持续改写的变量，
两次读到不同值才是对的。

想要"跑完之后紧接着的那个现场"，用一条工作流把"跑"和"读"放进同一个会话，见
[`gu-inspect-state.md`](gu-inspect-state.md)。
