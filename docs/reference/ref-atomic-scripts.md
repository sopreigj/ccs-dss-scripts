# 原子层：结构、分类与约定

> 这一层共 18 个脚本，位于 `atomic/` 下按五类分目录。逐脚本的参数见
> [`ref-scripts.md`](ref-scripts.md)；本文讲**为什么这么分、文件怎么组织、约定是什么**。

## 1. 这一层负责什么

**一次调用做一件事，各开一个会话。**

- 负责：连接、运行控制、内存与寄存器读写、表达式求值、程序与 flash 操作。
- 不负责：需要连续动作、依赖会话内状态的流程——那些放进 `workflows/`。

判据只有一句：**这件事单独跑有意义吗？** 有 → 原子脚本；没有（必须"先 A 再 B 才能看到结果"）
→ 工作流。

## 2. 五个分类与各自的归属判据

| 目录 | 管什么 | 判据 |
|---|---|---|
| `target/` | 连接与运行控制 | 管的是**目标整体**的状态：连上、运行、停机、复位 |
| `program/` | 把程序放进目标 | 管的是**一次程序装载**及其校验，以及 flash 本身 |
| `memory/` | 内存 | 管的是**地址空间**（含内存映射的外设寄存器） |
| `register/` | CPU 寄存器 | 管的是**寄存器名空间**里的量，不是内存映射的外设 |
| `expression/` | 表达式 | 管的是**按符号或表达式**访问，需要符号表 |

**`register/` 与 `memory/` 的边界**是新人最容易搞混的一处：

- CPU 寄存器用寄存器名（如程序计数器、状态寄存器），走 `register/`；
- 外设寄存器（定时器、ADC 这些）是**内存映射**的，走 `memory/` 或表达式赋值。

## 3. 文件组织

```
atomic/<分类>/ccs12_2_0_<动作>.js     本体
atomic/<分类>/ccs12_2_0_<动作>.vbs    启动器（同目录、同名、配对）
```

- **命名就是契约**：`ccs12_2_0` 是版本前缀，`<动作>` 用受控词汇表里的词
  （见 [`ref-terms.md`](ref-terms.md)）。新建脚本前先查词汇表，避免造同义词。
- **一对文件必须同目录**：启动器靠自身位置找同名 `.js`。
- **`workflows/` 下只有 `.js`，没有启动器**——工作流的参数多、也不适合弹框点。

## 4. 只读 vs 改状态

这个区分决定了启动器在**无人值守模式**下允不允许用默认值：

| 类别 | 非交互模式下的行为 | 哪些属于这类 |
|---|---|---|
| **只读** | 允许采用默认值 | 检查连接、报告目标状态、读内存、读寄存器、导出内存、校验程序 |
| **改状态** | **拒绝**采用默认值，参数必须写在命令行上 | 运行、停机、复位、运行 N 毫秒、装载程序、flash 操作、写内存、填充、导入、写寄存器、赋值、驱动引脚 |

**判据不是"它改不改目标"，而是"不给参数能不能跑对"。** 例如"校验程序"只读，
但它必须知道比对哪个固件文件，没有可信的默认值——所以它同样拒绝回落。

机器可核对的分类表在 `test/drive_checks.ps1` 顶部，且与每个启动器头部的声明**双向核对**：
哪一侧被悄悄改掉都会让装置变红。

## 5. 每个脚本共同遵守的约定

- 位置参数顺序固定（目标配置、固件、然后自己的参数），选项 `--名字 值`；
- 必须声明接受多少个位置参数，多余的会被拒绝；
- 地址带 `0x`；路径必须绝对；
- 退出前把目标停住（少数脚本刻意例外，各自标注）；
- 成败只看结果标记行；
- 文件开头有**逐字相同**的引导块（找共享库 + 确认装载），`test/verify_static.ps1` 机械复查。

## 6. 增删脚本时

- **新增**：查受控词汇表 → 定分类 → 声明位置参数个数 → 写引导块 → 配 `.vbs` →
  补 [`ref-scripts.md`](ref-scripts.md) 与测试装置表。完整清单见
  [`../dev/dev-adding-a-script.md`](../dev/dev-adding-a-script.md)。
- **删除**：删掉成对的两个文件；并在本文、[`ref-scripts.md`](ref-scripts.md)、
  `test/README.md` 的装置表里一起移除。**遗留的引用比缺文件更糟**。
