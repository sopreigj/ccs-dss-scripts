# 与另一套实现的差异

本项目是 CCS **12.2.0**（DSS 技术栈）的实现。同一时期还存在一个面向**另一个 CCS 版本**的
同目标实现，两者的脚本名与工作流**概念上对应**，但**不是同一个东西**。

> **本文只讲差异，且只讲会影响你使用的差异。** 两边都有的概念（一个脚本只做一件事、
> 会话是状态边界、工作流必须单会话）不在这里重复。
>
> **为什么会有两套**：CCS 换过一次脚本接口。同一块板上同样的调试动作，
> 两代的调用形状、判定方式、参数传递方式都不同，所以必须是两套代码。
>
> **为什么不写另一套的具体名字**：本文是用本仓库的人看的，**说清"哪一边是什么样"就够了**；
> 写出另一套的产品名与版本号，只会把两个仓库的文档互相绑死，一处改名两边都要动。

## 差异总表

| 维度 | 本栈（CCS 12.2.0） | 另一套（另一个 CCS 版本） | 实际影响 |
|---|---|---|---|
| **成败判定** | stdout 上的标记行 `CCS12_2_0_RESULT=OK/FAIL` | 进程退出码 0/1 | **最大的一处**：流水线的判定方式完全不同 |
| **入口运行器** | 安装根下的 `dss.bat` | 安装根下的 `run.bat` | 命令形态不同 |
| **参数传递** | 含 `=` 或空格的参数会让 cmd 解析中止（退出码 255，Java 都没起来） | 运行器原样透传，没这个问题 | 本栈必须走环境变量通道；那边可以直接写 |
| **脚本启动参数位置** | 从第 3 个位置起 | 从第 3 个位置起，但运行器会插入脚本名 | 两边都不建议直接 `node xxx.js` 裸调 |
| **语言约束** | Rhino ES3：不能用 `let`/`const`/箭头函数/模板串/`Object.keys`/`JSON.` | Node 现代语法可用；只有编排层要求 ES3 子集 | 本栈写 `.js` 的限制更硬 |
| **配置文件名** | `ccs12_2_0.conf` | 另一套自己的配置文件（键的含义相同） | 名字与解析实现不同 |
| **配置读取实现** | 内嵌在共享库里的一个小解析器（`.js` 侧）+ `.vbs` 侧解析器 | 独立的配置模块 | 本栈的 `.js` 与 `.vbs` 是两处实现，改配置格式要改两处 |
| **共享库文件数** | 3 个（会话、启动器配置、编排驱动） | 4 个（多一个独立的配置模块） | — |
| **工作流数量** | **9 个** | **8 个** | 本栈多一个有对应能力的脚本，见下 |
| **启动器无人值守** | 有非交互开关，一个框都不弹 | 没有对应的开关 | 本栈更适合无人值守的对话框路径 |
| **源码编码** | 脚本本体按平台字符集读，所以代码文件必须 ASCII | 无此限制 | 本栈 `.js`/`.vbs`/`.bat` 一律 ASCII |
| **接口能力对象数** | **14 个**（含符号、调用栈、引脚/端口、页表、选项等） | **8 个** | 那边少的那几个是**能力差异**，见第 6 节 |
| **重启到程序入口** | **有**（重启动作） | **没有**（只有复位） | 那边要靠工作流组合 |
| **列出寄存器** | **有** | **没有** | — |
| **地址反查符号** | **有** | **没有** | — |
| **求值成字符串** | **有**独立接口 | **没有**独立接口 | — |
| **只加载符号表** | **有** | **没有**（只能装载程序时捎带） | — |

> 上表里"接口能力对象数"与后面四行是**逐项核实过**的（依据是两侧安装目录里的接口定义），
> 不是估计。

## 1. 判败机制（最要紧的一条）

**本栈**：底层运行器不把脚本的退出状态变成自己的进程退出码。**五种情形实测，退出码全部是 0**：
自然结束、显式以 1 退出、显式以 7 退出、抛出未捕获异常、**脚本路径根本不存在**。
所以退出码既没有原因、也无法区分"跑完了"与"脚本没找到"。本项目因此把成败打在 stdout 的标记行上。

**另一套**：运行器把退出码透传出来，那边直接用 0/1 判定。

**对你的影响**：

- 本栈的流水线必须**解析标记行**（`findstr /b /c:"CCS12_2_0_RESULT=OK"`），不能读退出码；
- 两栈的"判定原语"（`examples/run_one_step.bat`）是**同名同契约**的，它负责把各自的判定翻译成
  一行 `STEP_VERDICT=OK/FAIL` 并自带 0/1 退出码——**这是唯一可以在两栈之间复用的那一层**；
- 反过来说：**不要**把本栈的"看标记行"结论搬到另一边，也不要以为那边的"看退出码"在这里成立。
  两边各自的说明都写在第 12 节 / 各自的对应章节。

## 2. 参数传递

本栈的 `dss.bat` 会在解析阶段处理命令行：**含 `=` 或空格的参数会让 cmd 直接中止**，
表现是 `... was unexpected at this time`、退出码 255、输出里连标记行都没有（运行时根本没起来）。
给参数加引号也救不了——引号会让 cmd 更早中止。

另一套的运行器原样透传参数，从未遇到这个问题。所以：

- **本栈**：带 `=` 的表达式走环境变量通道（`CCS_WRITE_EXPR` / `CCS_EVAL_EXPR` / `CCS_SYMBOLS`）；
- **另一套**：可以直接写在命令行上。

**不要因为"那边能写"就推断本栈也能写。**

## 3. 语言与编码

- 本栈的 `.js` 跑在 Rhino ES3 上：`let` / `const` / 箭头函数 / 模板串 / `Object.keys` / `JSON.`
  都不存在。遍历对象用 `for-in` + `hasOwnProperty`。
- 本栈的脚本按**平台字符集**读取源码，在中文 Windows 上是 GBK：所以 `.js`/`.vbs`/`.bat`
  一律 ASCII，中文只进 `.md`。非 ASCII 字节会被解错，甚至吞掉换行。
- 另一套用现代 Node，没有这两条限制（只有编排层要求 ES3 子集，因为共享源码可能被两栈复用）。

## 4. 工作流数量的差异（本栈多一个）

本栈有 9 个工作流，另一套有 8 个。多出来的那个是
`workflows/ccs12_2_0_bp_write_action.js`：在断点上挂一个**写动作**。

它为什么在本栈存在、在那边不存在，属于设计取舍而非能力缺失：那一侧把"断点 + 动作"这件事
留给了别的机制。使用时的判断很简单：**如果你要用这个能力，就在本栈用；在另一套上找它没有意义。**

## 5. 接口能力差异（哪些事只有一边能做）

这一节是**逐项核实**的结果（依据是两侧安装目录里的接口定义），不是估计。
"一边有、一边没有"的能力最容易在移植代码时踩空。

| 能力 | 本栈 | 另一套 |
|---|---|---|
| 重启到程序入口（重启动作） | **有** | **没有** |
| 列出寄存器 | **有** | **没有** |
| 地址 → 符号反查（给地址返回符号名） | **有** | **没有** |
| 求值成字符串的独立接口 | **有** | **没有** |
| 只加载符号表（不装载程序） | **有** | **没有** |
| 调用栈 | **有** | **没有** |
| 引脚 / 端口的专用接口 | 存在，但**只在模拟器上有意义** | **没有** |
| 页/地址空间与内存映射管理 | **有** | **没有** |
| 断点集合保存到文件 / 从文件加载 | **有** | **没有** |
| 全局断点 | 有 | 有（本项目都没用到） |

**两边一致的行为**（这些结论可以互相参照）：

| 行为 | 两边的实测结果 |
|---|---|
| 内存地址粒度 | **都是字节地址**：连续三个地址各写一个 16 位值，连续读回时三个值逐个出现（两栈读出的字节序完全相同） |
| 连接是否复位 | **都不复位 RAM**：写一个哨兵值到空闲内存，断开重连后仍读回同一个值 |
| 复位落点 | **都落在启动区**，不是程序入口 |
| 复位类型 | **枚举结果相同**：一个允许执行、一个存在但不可执行 |
| 断点跨会话 | **都不存活** |
| 断点命中判定 | 都只能停机后比对 PC 与断点地址 |

## 6. 不要照搬的东西

| 不要搬 | 原因 |
|---|---|
| "看标记行判成败" | 只在本栈成立；那一侧看退出码 |
| "参数里不能有 `=`" | 只在本栈成立；那一侧透传 |
| "代码必须 ASCII" | 只在本栈成立（源码编码按平台字符集） |
| "重启到程序入口" 这个动作 | 只在本栈存在；那一侧没有对应方法，照抄会直接报"不是函数" |
| "列出寄存器" / "按地址反查符号" | 只在本栈存在 |
| "求值一定给字符串" | 那一侧的求值可能返回**空**；两边的返回类型也不同 |
| 具体的调用名（如列 flash 操作、读寄存器的成员名） | 两代接口形状不同，照抄会得到"看着对但跑不了" |
| 某一侧的"未确证"结论 | 未确证 ≠ 另一侧也不确定；反过来也一样，实测结论只在**同一边**成立（上表"两边一致"的几项是例外，那几项是两边分别量过的） |

## 7. 反过来也要注意

如果你是从另一套过来的，最容易误判的是"**判败方式**"和"**参数能不能直接写**"这两条。
先在 [`../start/first-script.md`](../start/first-script.md) 里确认本栈的判定方式，再动手写流水线。
