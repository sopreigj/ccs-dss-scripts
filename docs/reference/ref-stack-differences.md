# 与另一套实现的差异

本项目是 CCS **20.0.1**（Node 脚本接口）的实现。同一时期还存在一个面向**另一个 CCS 版本**的
同目标实现，两边的脚本名与工作流**概念上对应**，但**不是同一个东西**。

> **本文只讲差异，且只讲会影响你使用的差异。** 两边都有的概念（一个脚本只做一件事、
> 会话是状态边界、工作流必须单会话）不在这里重复。
>
> **为什么会有两套**：CCS 换过一次脚本接口。同一块板上同样的调试动作，
> 两代的调用形状、判定方式、参数传递方式都不同，所以必须是两套代码。
>
> **为什么不写另一套的具体名字**：本文是用本仓库的人看的，**说清"哪一边是什么样"就够了**；
> 写出另一套的产品名与版本号，只会把两个仓库的文档互相绑死，一处改名两边都要动。
>
> **写这份文档的原则**：两套文档结构尽量镜像；**镜像不了的地方就写清差异**，
> 不为对称而隐去（本文第 6 节列的正是这些地方）。

## 差异总表

| 维度 | 本栈（CCS 20.0.1） | 另一套（另一个 CCS 版本） | 实际影响 |

|---|---|---|---|
| **成败判定** | 退出码 0/1，原因在输出里 | stdout 上的结果标记行（退出码不可靠） | **最大的一处**：流水线的判定方式完全不同 |
| **入口运行器** | 安装根下的 `run.bat` | 安装根下的另一个批处理入口 | 命令形态不同 |
| **参数传递** | 原样透传，含 `=` 与空格的表达式可直接写 | 含 `=` 或空格的参数会让 cmd 解析中止 | 那一边必须走环境变量通道 |
| **脚本启动参数位置** | 运行器插入脚本名，脚本从第 3 个位置起读 | 同样从第 3 个位置起读 | 两边都不建议直接裸调脚本 |
| **语言约束** | 现代 Node；只有编排层限 ES3 子集 | 全部脚本限 ES3 | 那边写脚本的限制更硬 |
| **源码编码** | 无限制 | 代码文件必须 ASCII（按平台字符集读取） | 那边多了编码约束 |
| **配置文件名** | `ccs20_0_1.conf` | 另一套自己的配置文件（键的含义相同） | 名字与解析实现不同 |
| **配置解析** | 独立的配置模块 | 内嵌解析器（脚本侧）+ 启动器侧各一处 | 那边改配置格式要改两处 |
| **共享库文件数** | 4 个 | 3 个 | — |
| **工作流数量** | **8 个** | **9 个** | 那边多一个能力脚本，见下 |
| **启动器无人值守** | **没有**"完全不弹框"的开关 | 有非交互开关，一个框都不弹 | 本栈无人值守要直接调 `.js` |
| **脚本引导块** | **没有**引导块（靠运行器与模块解析） | 每个脚本开头有一段逐字相同的引导块 | 那边的排障经验（引导块找不到库）不适用于本栈 |
| **验证装置形态** | 静态检查 + 参数层 + 真板冒烟 | 另有"镜像 + 桩运行器"的启动器装置 | 装置清单不同，见下 |
| **接口能力对象数** | **8 个** | **14 个**（含符号、调用栈、引脚/端口、页表、选项等） | 本栈少的那几个是**能力差异**，见第 5 节 |
| **重启到程序入口** | **没有**（只有复位） | **有** | 本栈要靠工作流组合 |
| **列出寄存器** | **没有** | **有** | — |
| **地址反查符号** | **没有** | **有** | — |
| **求值成字符串** | **没有**独立接口 | **有** | — |
| **只加载符号表** | **没有**（只能装载程序时捎带） | **有** | — |

> 上表里"接口能力对象数"与后面四行是**逐项核实过**的（依据是两侧安装目录里的接口定义），
> 不是估计。

## 1. 判败机制（最要紧的一条）

**本栈**：运行器把脚本的退出状态透传出来，所以退出码 0/1 可靠，流水线可以直接用退出码判断，
失败原因从输出里读。

**另一套**：运行器的进程退出码**不反映**脚本的成败（几种情形下都是 0），所以那边只能看
stdout 上的一次性标记行。

**对你的影响**：

- 本栈的流水线写 `if errorlevel 1` 就够；
- 两栈的"判定原语"（`examples/run_one_step.bat`）是**同名同契约**的，它把各自的判定翻译成
  一行 `STEP_VERDICT=OK/FAIL` 并自带 0/1 退出码——**这是唯一可以在两栈之间复用的那一层**；
- **不要**把另一套的"看标记行"结论搬过来，也不要把本栈的"看退出码"搬过去。

## 2. 参数传递

**本栈**：运行器原样透传参数，所以 `--set "x = 1"` 这种写法直接在命令行上就行。

**唯一的坑在 PowerShell**：用 `cmd /c "..."` 拼命令时，PowerShell 会先处理一遍引号，
内部引号可能被吃掉。稳妥做法：直接用 `cmd`，或让表达式从环境变量进来。

**另一套**：参数里出现 `=` 或空格会让 cmd 在解析阶段中止（运行时根本没起来，连标记行都没有），
所以那边**必须**走环境变量通道。

## 3. 语言与编码

- 本栈用现代 Node，**只有编排层与共享源码**被限制在 ES3 子集（因为它们可能与另一套共享）。
  其余脚本可以用当代语法。
- 另一套全部脚本都跑在 ES3 上（不能用 `let`/`const`/箭头函数/模板串等），
  而且源码按平台字符集读取，所以**代码文件必须 ASCII**。
- 所以"那边代码必须 ASCII"这条结论，在本栈不成立。

## 4. 工作流数量的差异（本栈少一个）

本栈有 8 个工作流，另一套有 9 个。多的那个是"在断点上挂一个写动作"。

**本技术栈没有对应能力**，所以本仓库**没有**这个工作流——不是遗漏，是差异。
使用时的判断很简单：需要那个能力就去另一套；在本栈找它没有意义。

## 5. 接口能力差异（哪些事只有一边能做）

这一节是**逐项核实**的结果（依据是两侧安装目录里的接口定义），不是估计。
"一边有、一边没有"的能力最容易在移植代码时踩空。

| 能力 | 本栈 | 另一套 |
|---|---|---|
| 重启到程序入口（重启动作） | **没有** | **有** |
| 列出寄存器 | **没有** | **有** |
| 地址 → 符号反查（给地址返回符号名） | **没有** | **有** |
| 求值成字符串的独立接口 | **没有** | **有** |
| 只加载符号表（不装载程序） | **没有** | **有** |
| 调用栈 | **没有** | **有** |
| 引脚 / 端口的专用接口 | **没有** | 存在，但**只在模拟器上有意义** |
| 页/地址空间与内存映射管理 | **没有** | **有** |
| 断点集合保存到文件 / 从文件加载 | **没有** | **有** |
| 在断点上挂一个写动作 | **没有** | 有对应工作流 |
| 全局断点 | 有 | 有（本项目都没用到） |

**两边一致的行为**（这些结论可以互相参照）：

| 行为 | 两边的实测结果 |
|---|---|
| 内存地址粒度 | **都是字节地址**：连续三个地址各写一个 16 位值，连续读回时三个值逐个出现（两栈读出的字节序完全相同） |
| 连接是否复位 | **都不复位 RAM**：写一个哨兵值到空闲内存，断开重连后仍读回同一个值 |
| 复位落点 | **都落在启动区**，不是程序入口 |
| 复位类型 | **枚举结果相同**：一个允许执行、一个存在但不可执行 |
| 断点跨会话 | **都不存活** |
| 断点命中判定 | 都只能停机后比对 PC 与断点地址 |

## 6. 确实无法镜像的地方（诚实清单）

写文档时我们尽量让两套的篇目与结构一致，但下面这些**无法镜像**，因此各自如实写成不同内容：

| 项 | 本栈 | 另一套 |
|---|---|---|
| 引导块 | 没有；共享库由运行器与模块解析定位 | 每个脚本开头有一段逐字相同的引导块 |
| 启动器无人值守 | 没有开关；无人值守直接调 `.js` | 有非交互开关，且改状态启动器拒绝用默认值 |
| 启动器装置 | 没有（本栈启动器不弹框，不需要覆盖那条路径） | 有"镜像 + 桩运行器"的装置，覆盖非交互分支 |
| 源码编码约束 | 无 | 代码文件必须 ASCII |
| 语言约束 | 只有编排层限 ES3 | 全部脚本限 ES3 |
| 断点写动作 | 无此能力 | 有对应工作流 |
| 能力对象 | 8 个 | 14 个（多的是上表那几项） |

## 7. 不要照搬的东西

| 不要搬 | 原因 |
|---|---|
| "只能看标记行判成败" | 只在那一边成立；本栈退出码可靠 |
| "参数里不能有 `=`" | 只在那一边成立；本栈透传 |
| "代码必须 ASCII" | 只在那一边成立 |
| "脚本开头必须有引导块" | 本栈没有这个东西；照着加会破坏本栈的结构 |
| "重启到程序入口" 这个动作 | 本栈没有对应方法，照抄会直接报"不是函数" |
| "列出寄存器" / "按地址反查符号" / "只加载符号表" | 本栈都没有 |
| "求值一定给字符串" | 本栈的求值**可能返回空**（例如没有返回值的 GEL 调用），调用方必须处理这一种结果 |
| 具体的调用名（列 flash 操作、读寄存器的成员名） | 两代接口形状不同，照抄会得到"看着对但跑不了" |
| 某一侧的"未确证"结论 | 未确证 ≠ 另一侧也不确定；反过来也一样，实测结论只在**同一边**成立（上表"两边一致"的几项是例外，那几项是两边分别量过的） |

## 8. 反过来也要注意

如果你是从另一套过来的，最容易误判的是"**判败方式**"和"**参数能不能直接写**"这两条。
先在 [`../start/first-script.md`](../start/first-script.md) 里确认本栈的判定方式，再动手写流水线。
