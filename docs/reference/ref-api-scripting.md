# 本技术栈接口参考（CCS 20.0.1 / 脚本接口）

> 这一篇回答的是"**这个接口到底有没有某个能力**"。每条结论标注证据等级，
> 等级的定义见 [`../start/start-here.md`](../start/start-here.md)。
> 与另一套实现的对照见 [`ref-stack-differences.md`](ref-stack-differences.md)。

## 0. 加载与启动

- 脚本由安装根下的运行器启动；运行器会把脚本名插在命令行里，**脚本自己从第 3 个位置起读参数**。
- 脚本语言是现代 Node，可以用当代语法；**只有编排层与共享源码**被限制在 ES3 子集
  （因为它可能与另一套实现共享），见 [`../dev/dev-language-constraints.md`](../dev/dev-language-constraints.md)。
- 输入与输出路径必须绝对：相对路径会被解析到与调用者无关的位置。
- 初始化时可以传一批选项：**脚本超时**、安装根位置（只有把脚本模块搬走时才需要）、
  **抑制调试器与 GEL 消息**、**把日志写进文件**。初始化返回的对象提供：配置目标、列出核、
  开会话、设置超时、启动 IDE、关闭。
- 会话对象上挂着 **8 个**能力对象（这是本接口的全部能力面）：

  | 对象 | 管什么 |
  |---|---|
  | `target` | 连接、断开、运行/停机、单步、复位、复位类型 |
  | `memory` | 装载/校验、读/写/填充、导出/导入（含二进制与格式） |
  | `registers` | 按名读写 CPU 寄存器 |
  | `expressions` | 求值（含 GEL 表达式） |
  | `breakpoints` | 断点增删改查 |
  | `globalBreakpoint` | 全局断点 |
  | `flash` | flash 操作与属性 |
  | `settings` | 调试设置读写 |

  **没有**符号、调用栈、控制台、工程、引脚/端口这些对象——见第 9 节。

## 1. 会话与目标控制

**能力：完整。**

- 打开会话、连接目标、询问运行状态、运行、运行一段时间后停机、停机、复位；
- **复位类型可以在运行时枚举**：接口直接给出一个"名字 → 是否允许"的映射（实测得到两项）；
- **`reset()` 的落点不是"程序入口"**，而是启动区；**本接口没有"重启到程序入口"这个方法**
  （见第 9 节），所以"复位后停在程序入口"要用工作流组合；
- 连接之外还有断开，以及一个"运行但立即返回控制权"的异步运行变体（工作流等待停机时用它）；
- 报告的**探针型号来自配置文件的身份声明，不是探测结果**。

## 2. 寄存器

**能力：有。** 按寄存器名读、写。

- **没有"列出全部寄存器"的接口**——寄存器名要自己知道；
- **写完回读可能不相等**：有些寄存器有被硬件强制的位或只读位。脚本因此不把不一致当失败。

> 另一套实现里有一个"列出寄存器"的入口；**本栈没有**。所以"列寄存器"这件事
> 在两边不可移植——见 [`ref-stack-differences.md`](ref-stack-differences.md)。

## 3. 内存

**能力：完整。** 读、写、填充、导出、导入。

- 位宽支持 8 / 16 / 24 / 32 / 40 / 48 / 64；
- **地址是字节地址**：相邻地址各自承载一个元素，奇数地址可以直接寻址（实测）；
- 除按地址读写，还支持：
  - **一次写多个值**；
  - **读一个值 / 写一个值**的便捷形式；
  - **装载/校验二进制程序**（给定起始地址），与装载/校验可执行程序并列；
  - **导出/导入**：带格式的文本形式（可指定格式、可追加）、原始二进制形式；
  - 支持的格式列表可以在运行时问（按页）；
- **写入会静默截断**：值放不进目标字长时不会报错，所以脚本自己在参数层拦下这种输入；
- 文本导出与内存导入的 `page` 参数位置不同，容易写错，脚本按各自形状分别收紧；
- 相对输出路径会落到与调用者无关的位置，所以本项目要求输出路径也绝对。

## 4. 断点与观察点

**能力：有。**

- 断点可以按**地址或符号/源码位置**添加，可以带属性添加；可以删除单个、清空全部；
- 断点有**属性对象**：可以创建属性、读写属性、按源码位置设属性、列出详细属性；
  **删除按标识进行**，没有"按位置删除"；
- 另有一个**全局断点**对象（不属于本项目的用法）；
- **观察点（硬件数据观察点）是硬件资源**，数量受目标上硬件资源预算限制；
- 切换观察点类型会**重建它的属性集合**，切换前拿到的属性标识之后失效，必须重新定位；
- **"断点被命中"没有直接接口**：只能停机后比对 PC 与断点地址，
  这也是为什么"停机 PC 不在断点地址"必须被如实报告为未命中；
- **没有"运行到光标位置"** 这类调用。

## 5. 表达式与 GEL

**能力：有，但比另一套窄。**

- 求值表达式；返回值可能是**空**（例如求值一个没有返回值的 GEL 调用）、也可能是整数或字符串。
  **调用方必须处理"空返回值"这一种结果**，否则会得到"看起来像失败"的行为；
- 赋值就是**求值一个赋值表达式**（没有独立的赋值接口）；
- GEL 表达式通过求值通道承载；
- **没有"加载 GEL 文件"的单独接口**；
- **没有"求值成字符串"的独立接口**（另一套有）。需要字符串结果时只能靠求值本身的返回类型；
- 按符号名求值需要会话里有符号表（装载程序会带，或显式指定固件文件）。

> 本栈**没有符号对象**：想"只加载符号表而不装载程序"、或"按地址反查符号名"，
> 在本栈都做不到——见第 9 节。

## 6. Flash

**能力：有，而且属性可读可写。**

- 支持的操作名由目标自己决定，**不能在代码里枚举**——脚本必须先问目标要列表
  （接口返回的是一个字符串，本项目把它拆开再逐项精确比对）；
- **操作名不带参数**：擦哪些扇区、密码写什么、频率测试用哪个引脚，全部来自当时的属性值；
- 属性可以在**同一个会话内**改写，从而做到"只擦某几个扇区"这类精细操作；
- 除通用操作入口，还单独提供若干具名操作（擦除、锁、解锁、算校验和、读校验和、频测起停、
  密码编程、耗尽恢复），以及一个"本器件是否支持 flash 编程"的查询；
- **多段装载**：有开始/结束两个调用，用于"只在第一次装载时擦 flash"这类场景。

**本仓库主动拒绝的两条路径**（都发生在打开会话之前，可离线复测）：

| 路径 | 拒绝理由 |
|---|---|
| 写安全模块密码 | 密码一旦写入且无人记得，擦除也需要先解锁，芯片等于报废 |
| 单独设置密码键 | 它是上一条的"上膛"动作 |

另有一个操作会置位安全模块里的锁定位，**可逆性未证明**：脚本保留它，但执行前打警告。

## 7. 设置（settings）

**能力：有。** 可以读当前调试设置、按名字写设置，也能一次取出**全部设置及其详情**。

- 设置项的名字与取值由目标决定，不能预先假定；取值可能是布尔、数值或字符串；
- 设置值只影响**当前会话**，不持久化——所以"设了属性再执行操作"必须落在同一次调用里。

## 8. 日志与事件

**能力：有限。**

- 可以打印日志（本项目用它来做所有输出）；
- 初始化时可以**把日志写进文件**，并可以**抑制调试器与 GEL 消息**；
- **没有断点命中事件、没有停机原因事件**。这类信息只能靠轮询状态与比对 PC。

## 9. 明确不存在的能力

| 想要 | 事实 |
|---|---|
| 符号对象本身（只加载符号、判断符号存在、取符号地址） | **没有**。只有"装载程序时顺带带进符号表"，以及"装载时显式指定符号文件" |
| 地址 → **源码行 / 符号反查** | **没有**。PC 只能给出地址，查源码行是 GUI 的活 |
| 调用栈 | **没有**（另一套实现有） |
| 控制台对象 | **没有** |
| 引脚 / 端口 / GPIO 的专用接口 | **没有**（本项目直接操作内存映射的寄存器） |
| 工程管理（打开/构建工程） | **没有**（本项目也不需要） |
| 枚举全部断点 | **没有**（只能按标识删除） |
| 列出全部寄存器 | **没有** |
| 运行到光标位置 | **没有** |
| "重启到程序入口"（重启动作本身） | **没有**。只有复位，而复位落在启动区 |
| 停机原因 | **没有**，只能比对 PC 与断点地址来推断 |
| 加载 GEL 文件 | **没有**独立接口，GEL 表达式走求值通道 |
| 求值成字符串 | **没有**独立接口；只能看求值本身的返回类型 |
| 断点/停机的回调事件 | **没有**，只能轮询 |

> 这一节是**逐条核实过**的：判据是安装目录里的接口定义，而不是"某处没找到"或"某个对象存在"。

## 10. 已经实测确认的行为

以下几条曾经是"未确证"，现在有实测结论。换芯片或换工具版本后要重新量。

| 问题 | 实测结论 |
|---|---|
| 连接目标会不会复位目标 | **不会复位 RAM**。判据：向一块空闲内存写一个哨兵值，断开、重连、再读，值保持不变 |
| 内存是字地址还是字节地址 | **字节地址**。判据：向连续三个地址各写一个 16 位值，连续读回时三个值逐个出现 |
| 复位类型的数量与可执行性 | **枚举到 2 个**：一个允许（落在启动区）、一个存在但**不允许** |
| `reset()` 的落点 | 落在**启动区**，不是程序入口；装载程序则落在程序入口 |
| 有没有"重启到程序入口"的动作 | **没有**（该动作在本接口里不存在，调用它会直接报"不是函数"） |
| 断点是否跨会话存活 | **不存活**（与另一套实现一致：会话结束即销毁） |

## 11. 仍未确证（不要当结论用）

以下问题仍没有可靠证据。它们**不是"不可用"**，只是没人量过：

| 问题 | 状态 |
|---|---|
| flash 属性的作用域（会话内还是全局） | 未在本栈单独验证。因此脚本一律把属性与操作放在**同一次调用**里 |
| 某些复位类型存在但不可执行的原因 | 只知道现象，不知道原因 |
| 观察点的"跳过前 n 次触发"选项的**实际效果** | 选项名可以设进去，但效果没有单独验证 |
| 多核目标上的会话选择与同时操作 | 未测（本项目是单核目标） |
| 初始化选项里"抑制消息"与"写日志"的粒度 | 只确认了选项存在，没有逐项验证边界 |

**做法**：任何依赖上述性质的设计都必须显式声明依赖，或者干脆不依赖。

## 12. 关键文件在哪

随 CCS 安装自带的接口定义文件与参考文档都在**安装根目录**下（具体位置由配置键 `CCS_ROOT` 决定）。
需要确认某个能力时，**以那里的接口定义为准**，不要凭界面经验推断——
本节多数结论就是从那份定义逐项核出来的。

## 13. 与另一套实现的接口差异（摘要）

| 维度 | 本栈 | 另一套 |
|---|---|---|
| 成败判定 | 退出码 + 输出里的原因 | stdout 上的结果标记行（退出码不可靠） |
| 参数传递 | 运行器原样透传 | 运行器会吃含 `=` 或空格的参数 |
| 语言 | 现代 Node（编排层限 ES3） | 全部脚本限 ES3 |
| 源码编码 | 无限制 | 代码必须 ASCII（按平台字符集读取） |
| 会话库文件数 | 4 个 | 3 个 |
| 能力对象 | 8 个（无符号、无调用栈） | 14 个（含符号、调用栈、引脚/端口） |
| 重启到程序入口 | **没有** | **有** |
| 列出寄存器 | **没有** | **有** |
| 地址反查符号 | **没有** | **有** |
| 求值成字符串 | **没有**独立接口 | **有** |

完整清单与"别照搬"清单见 [`ref-stack-differences.md`](ref-stack-differences.md)。
