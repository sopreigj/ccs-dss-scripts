# 配置参考

## 1. 这是什么

一个仓库根的本地文件 **`ccs20_0_1.conf`**，保存**机器相关**与**项目相关**的值。
随仓库发布的是模板 `ccs20_0_1.conf.example`；真正的配置文件**不入库**（已在忽略清单里）。

为什么要有它：脚本不能假设你的 CCS 装在哪、你的工程在哪。把这些值集中在一个文件里，
脚本本体就与机器无关，整个仓库可以搬到任何位置。

## 2. 七个键

| 键 | 含义 | 缺省时 |
|---|---|---|
| `CCS_ROOT` | CCS 安装根目录（`run.bat` 在其下） | 报错 |
| `CCXML` | 目标配置文件（决定仿真器与芯片） | 报错 / 空预填 |
| `OUT` | 固件文件（同时是符号表来源） | 报错 / 空预填 |
| `EVAL_EXPR` | 默认读回的表达式 | 报错 / 空预填 |
| `WRITE_EXPR` | 默认的赋值表达式 | 报错 / 空预填 |
| `WATCH_ADDR` | 默认观察点地址（必须填"固件持续写"的地址） | 报错 / 空预填 |
| `SETTLE_MS` | 写变量前先让程序跑多少毫秒 | 报错 / 空预填 |

前三个是**路径键**，后四个是**固件配方键**（换固件时改这四个）。

## 3. 文件格式

```ini
# 以井号开头的整行是注释
CCS_ROOT=<你的 CCS 安装根>
CCXML=<你的目标配置文件>
OUT=<你的固件文件>

EVAL_EXPR=your_symbol.Var
WRITE_EXPR=your_symbol.Var = 1
WATCH_ADDR=0x0000
SETTLE_MS=500
```

解析规则：

- `键=值`，**等号左侧不留空格**；值取到行尾整段，所以值里可以有空格和 `=`；
- 键名大小写不敏感；
- 文件是 UTF-8；行尾用 CRLF；
- 不支持行尾注释（`值 # 注释` 里的注释不会被识别）。

## 4. 优先级：按键、按入口分别成立

**这不是一条公式，而是每个键、每个入口各自的一条链。** 三个入口的链不同：

### `.vbs` 启动器

| 键 | 覆盖链（高 → 低） |
|---|---|
| `CCS_ROOT` | 环境变量 `CCS20_0_1_ROOT` > 配置文件 > **报错** |
| `CCXML` / `OUT` | 命令行参数 > 对话框输入 > 环境变量 > 配置文件 > **空预填** |
| 配方四键 | 对话框输入 > 配置文件 > **空预填** |

### `examples\*.bat`

| 键 | 覆盖链（高 → 低） |
|---|---|
| `CCS_ROOT` | 配置文件 > 继承来的 `CCS_ROOT` > **报错并 exit 1** |
| `CCXML` / `OUT` | 位置参数 > 环境变量 > 配置文件 > **报错并 exit 1** |
| 配方四键 | 配置文件 > **报错并 exit 1** |

### 直接调 `.js`

脚本（经运行器启动）**也读同一个配置文件**：省略前导路径参数（目标配置、固件）时从配置文件补齐；
显式给了路径就优先用你给的。

规则是**全给或全不给**：只给目标配置、不给固件，仍然是用法错误（不会"补一半"）。

## 5. 缺键即报错（没有内置回落）

配置文件缺某个键时（或文件本身不存在时）：

- `.bat` 打印自己的失败信息并以 1 退出；
- `.vbs` 弹窗**空预填**；
- `.js` 在确实需要该键时报用法错误，并提示去复制示例文件。

**没有"猜一个默认值"这条路**：参数写错就报错，不替你补。

## 6. 什么该进配置

进配置的判据是"**换机器或换项目时必须改，而且不该改代码**"：

| 该进 | 不该进 |
|---|---|
| CCS 安装位置 | 脚本内固定的行为参数（如单步类型） |
| 你的工程路径、固件路径 | 一次实验用的临时值 |
| 固件相关的默认表达式与地址 | 与机器无关的约定（地址必须带 `0x`） |
| 与启动时序有关的等待时长 | 速率、超时等可以按次传的参数 |

**新增一个键的真实代价**：解析器、错误文案、示例文件、本文件的三条覆盖链表、
以及那些要读它的脚本——四处到六处要同时改，而且旧配置文件不会因此报错（只会缺键）。
所以加键要谨慎，能作为参数传的就不要做成键。

## 7. 换机器 / 换项目的检查清单

1. 复制一份示例，改名成 `ccs20_0_1.conf`；
2. 填 `CCS_ROOT`（CCS 装在哪）；
3. 填 `CCXML`（这次要连的目标与仿真器）；
4. 填 `OUT`（这次要烧的固件）；
5. 填配方四键（这次要读写的表达式与地址）；
6. 跑一次 `check_connection` 验证装对了；
7. 如果换了仿真器型号，按 [`../start/setup.md`](../start/setup.md) 第 5 节核对身份。

**只改这一个文件，不改任何脚本。**

## 8. 常见问题

**设了环境变量却"没生效"？** 先看它管的是什么：`CCS20_0_1_ROOT` **只决定运行器在哪**，
它换不了板子，也换不了固件——那两样看 `CCXML` 与 `OUT`。

**换了板子但脚本还连着旧的？** 改 `CCXML`。注意散落多份同名配置文件的情况，
确认你改的是配置键指向的那一份。

**只想临时换一次？** 用命令行参数（`CCXML` / `OUT` 支持），或给这次调用设环境变量——
不要为了临时改动去编辑配置文件。

**配置文件能提交吗？** 不能。它里面是你的机器与工程信息，已在忽略清单里。
