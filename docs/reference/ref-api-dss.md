# 本技术栈接口参考（CCS 12.2.0 / DSS）

> 这一篇回答的是"**这个接口到底有没有某个能力**"。每条结论标注证据等级，
> 等级的定义见 [`../start/start-here.md`](../start/start-here.md)。
> 与另一套实现的对照见 [`ref-stack-differences.md`](ref-stack-differences.md)。

**取证来源**（都是随 CCS 安装自带的材料，位置由配置键 `ccs_root` 决定）：

| 来源 | 是什么 | 能回答什么 |
|---|---|---|
| **接口定义（逐类）** | 调试引擎的 Java 接口文档：会话、目标、内存、断点、表达式、flash、符号、调用栈、引脚/端口、复位类型、属性、选项、内存映射、页表等 | **"有没有这个能力"** 的权威依据；每个类的成员逐个列出 |
| **入口类接口定义** | 脚本环境单例（提供服务器入口、工作目录、路径换算、超时、日志追踪） | 如何拿到会话、如何设置超时与日志 |
| **服务器类接口定义** | 调试服务器（开会话、设配置、测连接、列核、列寄存器、建立目标配置编辑器/生成器） | 会话之外的那些能力 |
| **官方用户指南** | 脚本相关章节：环境、例子、断点、传参、调试属性、GEL、多会话、日志、性能分析 | 使用方式与官方立场 |
| **DSS 手册** | 与上面同源的完整手册 | 上面几项的细节补全 |
| **官方示例** | 随安装发布的示例脚本（含设备专用例子） | 真实调用形状 |
| **芯片属性定义** | flash 属性的定义文件（扇区地址、默认值、允许范围） | flash 操作的精确边界 |

> **判据**：说"有"要能指到某个类的某个方法；说"没有"要说明在哪里都找不到。
> 只凭"某个对象存在"或"某处没找到"下结论，两边都会错。

## 1. 会话生命周期

**能力：完整。** 建立配置、打开会话、连接目标、在结束时销毁会话。

- 每个脚本都自带一段引导块，负责找到并装载共享库，再断言装载成功；
- 会话对象在脚本内持有，脚本拒绝时会确保目标被停住；
- **会话结束时它的所有子对象都被销毁，没有"重新挂上"的接口**。这是"跨脚本状态不保持"的
  根本原因，也是工作流必须写成一个脚本的原因。**这一条是实测的**（见第 11 节：断点不跨会话存活）；
- 会话可以设置一个**脚本超时**：底层调用等太久就抛出来，而不是无限等。工作流里等待停机时用它兜底；
- 会话对象还能给出**它自己的一批身份信息**：用的是哪份目标配置、板名、核名、芯片型号、
  族/指令集/平台，以及一批运行输出（标准输出与标准错误的缓冲内容、以及把目标输出重定向到文件）。
  本项目只用了其中一部分（板名、核名、芯片型号）——其余是"存在但没用"的能力。

## 2. 程序装载与校验

**能力：完整。** 装载固件（同时把符号表带进会话）、校验目标内容与固件是否一致。

- 装载结束后目标通常停在程序入口；
- 校验是只读的：读回目标内容与文件比对，不一致就算失败。

## 3. flash 操作

**能力：有，而且属性可读可写。**

- 支持的操作名由目标自己决定，**不能在代码里枚举**——脚本必须先问目标要列表；
- **操作名不带参数**：擦哪些扇区、密码写什么、频率测试用哪个引脚，全部来自当时的属性值；
- 属性可以在**同一个会话内**改写，从而做到"只擦某几个扇区"这类精细操作；
- **属性是会话级的**：在一个会话里改过，新会话读回的是默认值。
  所以"改属性 + 执行操作"必须落在**同一次调用**里，分开两次调用等于没改；
- 属性的类型不统一（有布尔、有字符串、有数值），取值前要先问它的类型，否则会取错；
- 一次擦除的覆盖范围、扇区地址边界、属性默认值，都以芯片的 flash 属性定义文件为准。

**本仓库主动拒绝的两条路径**（都发生在打开会话之前，可离线复测）：

| 路径 | 拒绝理由 |
|---|---|
| 写安全模块密码 | 密码一旦写入且无人记得，擦除也需要先解锁，芯片等于报废 |
| 单独设置密码键 | 它是上一条的"上膛"动作——封操作名不封它等于收枪不收子弹 |

另有一个操作会置位安全模块里的锁定位，**可逆性未证明**：脚本保留它，但执行前打警告。

## 4. 目标状态与复位

**能力：状态需要组合着问；复位类型可以枚举。**

- 核名、是否连接、是否停机这些要分别取；PC 则通过求值取得；
- **复位类型可以在运行时枚举**：先问数量，再按下标取每一项；每一项能给出名字、说明，
  以及**是否允许执行**；
- **`reset()` 与 `restart()` 的落点不同**（实测）：前者落在启动区，后者落在程序入口。
  所以"复位后停在程序入口"用后者，或者用工作流组合；
- 有一类复位类型**存在但不可执行**——所以"在列表里"不等于"能跑"，执行前要看它的允许标志。

## 5. 断点与单步

**能力：有，但只能按标识删除。**

- 断点可以按**地址**、按**符号名**、按**源码文件+行号**三种方式设置；
- 也可以先创建"属性对象"，再按属性设置（数据观察点走的就是这条路）；
- 断点的删除接口只接受标识，没有"按位置删除"或"枚举全部断点"的接口；
- 断点集合可以**保存到文件 / 从文件加载**——这是跨会话重建断点的唯一办法
  （见第 11 节：断点本身不跨会话存活）；
- 单步分源码级、汇编级、上下文级；
- **"断点被命中"没有直接接口**：只能停机后比对 PC 与断点地址，这也是为什么"停机 PC 不在断点地址"
  必须被如实报告为未命中。

## 6. 表达式与符号

**能力：有；赋值就是求值一个赋值表达式。**

- 没有独立的 `assign` 接口；
- 整数求值给整数结果，另有一个**给字符串结果**的求值接口（本项目的 CSV 单元格用它来保持列格式稳定）；
- 按符号名求值需要会话里有符号表（装载程序会带，或显式加载）。

符号对象本身的能力（**这是本项目此前没有用到的一面**）：

| 能力 | 说明 |
|---|---|
| 只加载符号 | 只加载符号表而不装载程序——"我要按名字读，但不想动 flash"时用它 |
| 判断符号存在 | 及**类型定义**（结构体、类）会被判为"不存在"，因为它们没有目标地址 |
| 取符号地址 | 同上：类型定义没有地址 |
| **地址 → 符号（反查）** | 给定页与地址，返回该地址上的符号；还有一个返回**全部**匹配符号的版本 |
| 按偏移加载 | 支持代码段/数据段各自偏移，以及相对偏移 |
| 段大小 / 隐藏段 / 卸载 | 用于多符号文件的场景 |

> 反查这一条值得单独记住：它可以回答"这个 PC 落在哪个函数里"，
> 只是**给的是符号名，不是源码行**——源码行仍然要 GUI。

## 7. 内存与寄存器

**能力：完整。** 读、写、填充、导出、导入，以及 CPU 寄存器的读写。

- 位宽支持 8 / 16 / 24 / 32 / 40 / 48 / 64；
- **地址是字节地址**：相邻地址各自承载一个元素，奇数地址可以直接寻址。
  （实测：向连续三个地址各写一个 16 位值，连续读回时三个值逐个出现。）
  所以**不能**把"字地址"的直觉套在这里：`0x1000` 与 `0x1001` 是两个不同的位置；
- 除按地址读写，还支持：
  - **按段名填充**（给一个段，整段填同一个值）；
  - **批量写**：一次写多个值；
  - **原始二进制读写**（可指定位数、字节序），以及带格式的保存/加载；
  - 多字长版本的读写（用目标默认字长，不指定位宽）；
- 导出有若干格式常量可选，还有二进制形式；格式列表可以在运行时问；
- **写入会静默截断**：值放不进目标字长时不会报错，所以脚本自己在参数层拦下这种输入；
- 文本导出的 `page` 参数与内存导入的 `page` 参数位置不同，容易写错，脚本按各自的形状分别收紧；
- 相对输出路径会被解析到与调用者无关的位置，所以本项目要求输出路径也绝对。

**页/地址空间的对象**（本项目没有用到，但存在）：可以按地址查页、做正反查，
以及通过一张表增删/启用地址范围映射。

**寄存器**：读、写都在内存对象上（没有独立的寄存器对象）。

## 8. 引脚 / GPIO

**能力：实机上没有可用接口。**

- 相关的对象在接口里存在，但**只在模拟器上有意义**；
- 因此本项目驱动引脚的方式是**直接操作内存映射的寄存器**（见
  [`../guides/gu-debug-target.md`](../guides/gu-debug-target.md) 与 `pin_drive` 工作流），
  并在写入前检查该引脚是否已被固件占用。

## 9. 目标配置与仿真器识别

**能力：有，但是"读配置"而不是"探测硬件"。**

- 能报告当前会话用的是哪份目标配置、连接类型、核名；
- 另外还有两个独立于会话的入口：**测连接**（不用开会话就能试通不通）与**列出可用核**
  （多核目标用得上）；
- **报告的探针型号来自配置文件的身份声明**。所以"配置里写 v2、手上插 v1"仍会连接成功，
  并显示 v2。要确认身份必须人工对账，见 [`../start/setup.md`](../start/setup.md)。
- 连接本身还有一个**不等目标的变体**：可以在目标尚未进入可用状态时就返回，
  而不是一直等下去。

## 10. 明确不存在的能力

| 想要 | 事实 |
|---|---|
| 地址 → **源码行** | **没有**。地址能反查到**符号名**（见第 6 节），但查不到源码行——那是 GUI 的活 |
| 停机原因 | **没有**。只能比对 PC 与断点地址来推断 |
| 枚举全部断点 | **没有**，只能按标识删除 |
| 运行到光标位置 | **没有**对应的调用 |
| 引脚 / GPIO 的专用接口 | 实机上没有（只有模拟器有意义） |
| 独立的赋值接口 | **没有**，赋值是求值一个赋值表达式 |
| 按位置删除断点 | **没有**，只能按标识 |

> 这一节是**逐条核实过**的：不要凭"某个对象存在"就以为它的每一项能力都存在，
> 反过来也不要用"某处没找到"当作不存在——判据是接口定义本身。

## 11. 已经实测确认的行为

以下几条曾经是"未确证"，现在有实测结论。**做法**：任何依赖它们的代码都可以放心依赖，
但换芯片或换工具版本后要重新量。

| 问题 | 实测结论 |
|---|---|
| 连接目标会不会复位目标 | **不会复位 RAM**。判据：向一块空闲内存写一个哨兵值，断开、重连、再读，值保持不变（连续三次连接）。对照：写进固件自己的变量区，同样的路径读回的是固件写入的值——说明保持性来自"没人写"，而不是"复位了但恰好没动它" |
| 内存是字地址还是字节地址 | **字节地址**。判据：向连续三个地址各写一个 16 位值，连续读回时三个值逐个出现 |
| flash 属性的作用域 | **会话级**。判据：在一个会话里把一个扇区选择属性改成"不选"，**新会话**读回的是默认值（全选） |
| 断点是否跨会话存活 | **不存活**。判据：会话 A 装载程序并在某个运行期地址设断点，会话 B 不设断点直接运行——**永远不命中**（带脚本超时保护） |
| 复位类型的数量与可执行性 | **枚举到 2 个**：一个可执行（落在启动区）、一个**存在但不可执行** |

## 12. 仍未确证（不要当结论用）

以下问题仍没有可靠证据。它们**不是"不可用"**，只是没人量过：

| 问题 | 状态 |
|---|---|
| 某些复位类型"存在但不可执行"的原因 | 只知道现象，不知道原因 |
| 连接时那个"不等目标"的变体在什么场景下有用 | 未测 |
| 观察点的"跳过前 n 次触发"选项的**实际效果** | 选项名可以设进去，但效果没有单独验证 |
| 断点配置文件（保存/加载断点集合）在跨会话时能否复原断点 | 未测。它与"断点不跨会话存活"不矛盾——那是靠文件显式重建 |
| 多核目标上的会话选择与同时操作 | 未测（本项目是单核目标） |

**做法**：任何依赖上述性质的设计都必须显式声明依赖，或者干脆不依赖。

## 13. 为什么本项目不读退出码（本栈特有）

底层运行器的进程退出码**不反映脚本的成败**。**五种情形实测，进程退出码全部是 0**：

| 脚本里的情形 | 进程退出码 |
|---|---|
| 自然结束 | 0 |
| 显式以 1 退出 | 0 |
| 显式以 7 退出 | 0 |
| 抛出未捕获异常 | 0 |
| **脚本路径根本不存在** | 0 |

原因与运行器自身的实现有关：它启动一个运行时进程，脚本的结束状态没有变成它自己的退出码。
后果是**退出码里既没有原因，也无法区分"跑完了"与"脚本没找到"**。

所以本项目改用 stdout 上的一次性标记行作为唯一判据，见
[`../dev/dev-launcher-contract.md`](../dev/dev-launcher-contract.md)。另一套实现的
运行器会把退出码透传出来，那边就用退出码——这是两栈最容易搞混的一处差异。
