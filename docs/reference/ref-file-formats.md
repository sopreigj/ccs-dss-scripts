# 产出与文件格式

脚本会产生两类文件：**导出的内存**与**采样的 CSV**。本文说明它们的格式、落点与往返验证方法。

> 本文件在结构与结论上与另一套实现的同名文档**一致**——
> 格式与落点不受接口版本影响。

## 1. 通用规则

- **所有输入与输出路径都必须绝对**。相对路径会被解析到与调用者无关的位置，
  于是"文件写到哪去了"不可知。脚本对输入与输出**同样**要求绝对路径。
- 脚本不替你创建目录：目标目录必须已存在。
- 失败时不会留下"半个文件"当作成功：导出失败会以失败退出（退出码 1）。

## 2. 内存导出（`mem_export`）

```
ccs20_0_1_mem_export.js <ccxml_path> <address> <count> <file> [--format <格式>] [--binary] [--page data] [--append]
```

| 参数 | 含义 |
|---|---|
| `<address>` | 起始地址，必须带 `0x` |
| `<count>` | 导出多少个元素 |
| `<file>` | 输出文件（绝对路径） |
| `--format` | 文本导出的格式；给定了不认识的格式会报错而不是静默忽略 |
| `--binary` | 导出为二进制（此时不接受文本格式参数，两者互斥，同时给会报错） |
| `--page` | 程序空间或数据空间 |
| `--append` | 追加而不是覆盖 |

导出的文本是**带地址的十六进制转储**（每行一个地址加若干字），格式与芯片厂商的通用样式一致。
二进制形式就是原始字节，适合再喂给别的工具。

**为什么有这个脚本**：在擦写 flash 之前先把要动的那一段导出成文件，是最省事的回滚手段。

## 3. 内存导入（`mem_import`）

两种形状，位置参数个数不同：

```
ccs20_0_1_mem_import.js <ccxml_path> <address> <count> <file> [--page data]      ← 文本形
ccs20_0_1_mem_import.js <ccxml_path> <address> <file> --binary [--page data]    ← 二进制形
```

**二进制形不接受个数参数**：整个文件都会导入。如果给它一个个数，脚本会明确报用法错误——
因为那会让人以为"导入被限制在这个长度"。

**往返验证**：一个稳妥的自检方式是"导出 → 修改 → 导入 → 再导出"，比较两次导出的内容；
或者反过来"导入 → 读几个字 → 比对"（记得用同一块空闲内存，避免固件同时也在写）。

## 4. 采样 CSV（`sample_exprs`）

```
ccs20_0_1_sample_exprs.js <ccxml_path> <out_file_path> <interval_ms> <count> <csv_file> <expr1> [expr2 ...]
```

| 列 | 含义 |
|---|---|
| 第 1 列 | **实测**时间戳：从采样开始到这一次取值的真实耗时（毫秒） |
| 其余列 | 每个表达式一列，值按"适合机器解析"的格式写（整数是 `0x` 形式） |

两条要记住的语义：

- **时间列是实测值，不是名义间隔**。目标与调试器的抖动都包含在里面。
- **采样不会停住目标**。每次取值是一个瞬时读，多字长的变量可能被抓到"改到一半"的状态。
  要把值当成精确断言，请先停机再读（用工作流）。

某次表达式求值失败时，该单元格会写成错误文本，**整批不会被丢掉**，最后以失败退出收尾。

## 5. 临时文件

验证装置会在系统临时目录下生成文件，**不进入仓库**：例如参数层装置用到的临时探针文件、
静态检查的镜像目录等，跑完即删。

导出的 hex / CSV 由**你**决定放哪（脚本要求绝对路径）。
忽略清单里已经排除常见产物（`.out` / `.ccxml` / `.hex` / `.bin` / `*.csv` / `*.log`），
所以你不会误提交它们。

## 6. 与另一套实现的差异

格式与落点**一致**（两边都用带地址的十六进制转储、都在 CSV 里写实测时间列）。
差异只在文件名前缀、判定方式与语言约束上，见
[`ref-stack-differences.md`](ref-stack-differences.md)。
